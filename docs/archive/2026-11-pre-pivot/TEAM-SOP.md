## 2. 工作流路由与本次判定

| 场景 | 判定条件 | 工作流 |
|---|---|---|
| 小型需求 | ≤10 源文件、单页应用 | 快速模式（工程师→QA） |
| Bug 修复 | 明确 Bug、非新功能 | BugFix 快捷路径 |
| **中大型需求** | **多模块、涉及底座重构、>10 源文件** | **标准 SOP（本次采用）** |
| 仅分析 | PRD / 架构评审 / 调研 | 部分工作流 |

**本次判定：标准 SOP**。理由：涉及 L0–L2 底座重构、8 个产品站点、零件注册中心、构建链改造，文件数远超 10，且用户明确要求"底层架构深度调整、保证复用/扩展/稳定"。

### 标准 SOP 阶段门

```
用户需求
  → [G1] 产品经理：增量 PRD
  → [G2] 架构师：系统设计 + 任务分解
  → [G3] 工程师：批量实现 + 全局一致性审查 IS_PASS
  → [G4] QA：测试 + 智能路由判定
  → 主理人汇编交付
```

每个阶段门为准出条件，未通过不得进入下一阶段。

## 5. 质量关卡

1. **工程师全局一致性审查**：所有文件写完后逐项核对接口、命名、路径、导出，`IS_PASS: YES` 方可交 QA。
2. **QA 智能路由判定**：
   - 源码 Bug → 路由 `Engineer`，附失败用例与错误信息
   - 测试代码 Bug → 路由 `QA`，自行修复
   - 全部通过 → 路由 `NoOne`
3. **最多 2 轮回归**：第 1 轮发现问题反馈修复，第 2 轮回归验证；2 轮仍不过则输出报告标注遗留问题，不得报"通过"。
4. **本地验证优先**：所有构建/类型/测试在本地通过后才允许声称完成，禁止以 HTTP 200 或"看起来没问题"代替实测。

## 7. 后续叠加组合的标准流程（面向扩展性）

用户明确："后续的叠加组合可能会更加复杂，要保证复用、扩展、稳定。"因此新增一个组合产品必须走：

1. **声明而非编码**：在站点注册表追加一条配置，声明 `scene / interaction / artifact / audio / narrative` 五层的零件组合。
2. **零件先入库**：新零件放入 `shared/parts-library/<id>/`，在零件清单登记来源与 `createPart(opts) => { update(t), dispose() }` 契约。
3. **不改底座**：不修改 `shared/core/`、不修改构建脚本、不修改其他站点目录。
4. **自动化验证**：`npm run build:all` → 全站哈希比对（仅新增站应有新产物）→ 合规断言 → 冒烟。
5. **回归门**：任一既有产物哈希变化即判定失败，回到零件组合配置排查。

稳定 = 既有产物零变化；扩展 = 新增只追加配置；复用 = 五层零件全部来自注册中心。

### R6 处置裁决（主理人，G3 开工前置）

**事实**：`shared/core/BASELINE.sha256` 记录的是另一版 core 的哈希，与仓库实际提交的 11 个 core 文件逐字节不符；`dist/*.html` 7 站产物哈希与 `tests/baseline-dist.sha256` **7/7 OK**，说明产物基线是自洽的，坏的是 core 校验清单。

**裁决**：
1. **Frozen Core 的 11 个源码文件一个字节都不动**（INV-1 保持）。
2. 只允许用 `node shared/build/verify-core.mjs --generate` **重建校验清单** `BASELINE.sha256`，使其与实际 core 文件一致；这是修复失配的校验元数据，**不是篡改 Frozen Core 源码**。
3. 重建前后必须各做一次记录：重建前保存旧清单为 `docs/evidence/BASELINE.sha256.pre-fix`（只增证据文件），重建后 `verify:core` 必须 11/11 OK。
4. `tests/baseline-dist.sha256` **零改动**；重建后必须重新执行 `build:all` 并校验 7/7 产物哈希与既有基线逐字节一致，证明清单重建未改变产物字节函数 `f()`。
5. 由 G3 工程师执行，G4 QA 独立复验并在报告中标注「上游既有缺陷已修复，非本次改动引入」。
6. 若重建后 7 站产物哈希任一变化，立即停止并回传主理人，不得自行调整产物基线。

## 9. 信息流转规则

- 成员产出 → 回传主理人 → 主理人附完整上下文转交下一阶段成员。
- 分派下一阶段时，必须携带上一阶段产出的**完整路径与关键结论摘要**。
- 成员发现上阶段歧义 → 回传主理人 → 由主理人退回对应成员澄清，禁止成员间直连。
- 所有结论以成员产出为准，主理人仅编排与汇编。
