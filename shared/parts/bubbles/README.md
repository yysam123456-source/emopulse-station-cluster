# bubbles

**L2 生态**：深水里上浮的气泡群。

## 介质前提（先写这个，再写代码 —— §2.5b 的规矩）

底是**深水**（L0 水色 / L1 体素海），所以气泡是"发光的薄壳"，不是"有影的实体"：
- **`blend: 'screen'`**：气泡只加光不减光，叠在深色水上才亮得起来。用 `source-over` 会变成脏灰点。
- **高光是第二个更小的实心圆，不是径向渐变**：渐变在高光这种小尺度上只会糊成一团；两个实心圆的边界本身就是"壳"与"反光"的分界。这条是原文口径，bench 用 `createRadialGradient === 0` 锁着。

## 口径（来源 `src/components/showcases/AbyssalDescent.tsx` 第二个 effect，54 行）

| 项 | 值 | bench 断言 |
|---|---|---|
| 数量 | 70（`low` 档 24） | high `arc=140`、low `arc=48` |
| 半径 | `(0.6 + rand*2.2) * dpr` | — |
| 上升速度 | `(0.0004 + rand*0.0012) × 60` /秒 | reducedMotion 位移比 ≈0.30（实测 0.30） |
| 横向摆幅 | `0.3 + rand*0.9` | — |
| 高光 | `(x-0.3r, y-0.3r)` 半径 `0.35r`，`rgba(220,245,255,0.5)` | 几何误差实测 0.000px |

**一处必须说明的换算**：原文的 `speed` 是**每帧**位移（以归一化坐标计）。契约的时间单位是 `frame.t`（秒），所以这里**×60 换算成每秒**。不换算会慢 60 倍——气泡几乎不动，而"看起来还行"会让这个 bug 活很久。

## 成本（实测，不是估算）

`costMs = 0.27`，来源 `tests/bench-blend.mjs`（真 Chromium + Metal，1280×720@dpr2）：

| 项 | 实测 |
|---|---|
| 70 泡 × 2 圆的填充，`source-over` | 0.104 ms/帧 |
| 同上，`screen` | 0.156 ms/帧 |
| **`screen` 本身的代价** | **0.052 ms/帧** |
| 路径构造（140 段 × 0.8ms/千段） | ≈0.11 ms |
| 合计 | **0.27 ms** |

方法：把同一组气泡画 **50 遍**放大信号再除以 50 —— 直接测时效应小于本机噪声。
第一次用"每帧读 1 像素强制同步"的办法量出 **−1.00 ms**（负差值 = 纯噪声），这就是为什么必须放大信号。
**线性外推是上界假设**（GPU 饱和区更慢）；本机不可外推到低端集显/移动端。

## 纪律

`draw`/`update` 零 new、零闭包、零数组字面量、零 `Math.random`、零自持时钟。
`low` 档只改**绘制数量**，不重建数组、不改位置 —— 降档不该让画面"跳一下"。
`resize` 会按新 dpr 重建（半径含 dpr），同 seed 分布稳定。
