## 0. 一句话

四个站不是四个功能，是**四个不需要你回答任何问题的房间**。每间房只做一件事：头三秒让你知道「这里不要你做什么」，接下来一到四分钟你真的能停下来，离开时手上有一件能带出这个页面的东西。 **口径**：本期产品只做这四站；仓库里的 `/praise` 与 `/koi/*` 变体属于**冻结 legacy**——仍在注册表、有源码、**无构建产物**，不接入产品口径。

本期要验的**唯一一条产品假设**：

> **一个站成立，靠三件与架构无关的事：一个能脱站存在的产物 · 一个 ≥ 40s 的单向慢变量 · 首屏三层。**

**"零件数"不是产品主张，是工程台账**（在 §1.5）。这个数在本期四轮裁决里走成 **2 → 4 → 3 → 4 → 2**，每一次都是架构在动、不是产品在动。一个被架构裁决推着走的数，不该当产品定语——所以本文只用它估工，不用它判断"这个站成不成立"。

**站成不成立的判据换成可截图的三条**：① 首屏三层且只有三层；② 有一个 40 秒以上、单向、不可逆的变化；③ 离开时手上有一件能在站外打开的东西。**三条缺一，这个站不成立；零件装了几件不影响这三条。**

> **三条全中只说明这个站没有结构性缺陷，不说明它好看。** 它们是必要条件，不是充分条件——三道门都过、画面照样可能难看。下一份文档不许拿这三条当验收通过。

**成本指标：已撤（2026-11-19，主理人裁决）。**

原四个数——站内代码总量 ≤180 行 / 新增 ≤150 / 为停留新写 ≤60 / `L0–L4` 零件 ≤5——连同「>150 必须披露多出来的是什么」那条披露规则，一并删除。
原因一句话：主理人当期方向是**「无上限，我需要不断叠加补充」**，而这四个数全部是压住叠加的上限，两者不可能同时成立，护栏让位。
**删掉的是四个数字，不是「别浪费」这个意图**：报告里仍然打 `wc -l` 实数，只是不再有红线。

**`STAY` 开关表（保留）——它不是成本口径，是「关掉这件还能不能成立」的执行装置。**

每个停留文件头部放一张开关表：`export const STAY = { drift, dragLight, restamp, fold }`。
于是「逐件关闭测试」变成「逐个把 flag 置 `false` 各拍一张」，而不是「改逻辑再改回来」。

**死 flag 会被关闭测试自己抓出来**：置 `false` 后画面毫无变化 → 那段代码没在干活，删。所以这张表不会像其他声明式元数据那样静默腐烂——它**自带证伪**。
**但要知道它的上限**：STAY 只抓**死代码**（置 false 后毫无变化），抓不到**弱代码**（变了，但用户说不出哪里变）。所以 §2.2-A-4 那把尺（「差异必须能用一句话指出」）不能因为有了 STAY 就撤——**STAY 管存在性，A-4 管显著性，两把尺不重叠，不许合成一个**。

三把尺的分工（留档）：

| 尺 | 管什么 | 谁验 |
|---|---|---|
| **STAY 关闭测试** | 这段代码**有没有用**（置 false 后画面毫无变化 = 死代码） | 机器（逐个 flag，各截一张） |
| **§2.2-A-4** | 这个变化**看得见吗**（能不能用一句话说清哪里变了） | 人，30 秒 |
| **手测协议** | 有没有**偷偷留下结果**（编号/日期/宣言句不变、无第二入口、无计数） | 人，读文本前后比对 |

**注释和开关表都不得影响产物字节**：只写在 `sites/` 的源文件里（esbuild 会剥注释）。**不许进 `shared/parts/`，更不许出现在会被内联的模板字符串里**——WGSL 模板字符串里的注释会被当成源码打进产物，那是真体积。

**「2 件零件立住一个站」已从口径里删除**——T12 撤销后诚实的说法是「2 件零件 + 站内代码立住一个站」，§1.5 有实数。

## 1. 四座样板站的产品形态

### 1.0 四站共用的骨架（先定规则，后面逐站只写差异）

**进入**（头 3 秒）

- 可见元素只有三层：**H1（≤ 2 词）+ 一行 hook（≤ 12 词）+ 一个主按钮（≤ 3 词）**。
- 底材与后处理**不计入**这三层（它们是世界，不是界面）。
- 其余全部进 **Esc 二级菜单**：`Sound` / `Motion` / `Quality` / `About` / `Credits` / `Close`（`/hug` 多一项 `Wind`）。菜单内容四站一致。**全部终稿文案见 [`COPY-SITES.md`](./COPY-SITES.md) §2。**
- 首屏**不放**：风格切换器、画质三档、键位表、触屏提示常驻条、任何第二个按钮、任何页脚、任何跨站链接。

**沉浸**

- 必须存在一个**周期 ≥ 40s、单向、不可逆**的慢变量。不是循环动画——循环的东西看两眼就到底了，单向的东西用户会不自觉等它再走一点。
- 允许「什么都不做」算有效沉浸，但**必须真的能停住**：不点任何东西，画面也要在变。
- 停留目标 60–240s，不设上限，也不设奖励。

**带走**

- 必须是能脱离本站独立存在的东西。四种载体，**四站的主载体两两不同**：

| 载体 | 定义 | 判断标准 |
|---|---|---|
| **编号** | 无意义字符，有形状可念出，不必读懂 | 能对着电话念给对方听 |
| **链接** | 一段 URL，别人打开就能得到东西 | 不用注册、不用等待、不依赖我们是否在线知道 |
| **文本** | 一句有语义的话 | 粘进任何输入框都成立 |
| **图像** | 一张 PNG | 存进相册、离线打开 |

- 「看完了」「体验过了」「心情好一点了」**不是产物**。
- 带走入口出现的时机必须由**已发生的物理事件**决定（仪式完成 / 物体离场 / 时长 / 相位走完），不得由点击次数或完成度决定。

**角色分工：已撤（2026-11-19，主理人裁决）。**

原条：「复用只允许发生在 L4（后处理）与 L5（UI）；L0–L3 的零件不得在两站承担相同职责。」连同它下面那句理由（「世界的差异必须来自 L0–L2，否则四站就是同一套东西换皮」）一并删除。
**现在 L0–L3 的零件可以在两站承担相同职责，四站可以看起来是同一套东西。** 这一条与 §2.2-C 是同一次裁决。

**什么能做零件、什么只能站内代码（判定规则，两句并行，不许压成一句）**

> **按哪里都同义**（整屏草原、整个池面）→ 零件可以由 `frame.pointer.down` 的按下沿自触发。
> **语义绑在 UI 上**（按钮位置有意义、要免疫误触、要出阶段文案）→ 因果必须由站点持有，那件交互只能是站内代码。

技术事实（会反复用到，别记错）：零件的 `pointerdown` 是从 `host.ts:199` 挂在 **window** 上的，所以点 DOM 按钮也会冒泡进去——**零件看得见"某处被按了一下"，看不见"这次按下算不算一个决定"**。四站落位：`/license` 第二类（按钮在纸下方、章落在纸中央、还要出 `APPROVED`）· `/hug` 第一类（整片草原就是按钮）· `/koi` 属于"连续场输入"，读指针位置即可，没有"决定"语义。
最硬的一条封口是**出字**：任何能被读成一句话的文字只能由 L5/站点出（§1.4-3），所以"要出阶段名"的交互天然不可能在零件里。

### 1.1 `/license` · room

**一句话定义**：`A desk that issues a permit to rest.`

**情绪意图**（用户在什么状态下打开它）
> 你在床上躺了两个小时，什么都没做成，脑子里在给自己定罪。你不想被安慰，也不想谈感受，你想要一张**纸**，证明躺着是被允许的。

**进入**
- *看到*：一张米色纸占画面**面积 55–80%、宽高比 1.41（A4 横）**，正中、正矩形、无透视。（原写「约 78%」是错的：78% 面积 + 四边可见 + 真实纸张比例三者在 16:9/16:10 视口里**互斥**，只能取二。）纸上有极细的纤维纹与一圈压印的边线（**暗角不在纸上**——它属于镜头，落在纸外的桌面上）。一道斜的晨光带从左上落在纸上。**「光里有浮尘」这条尚未验证，按未实现计**，不写进验收。纸是**空白**的——它还不是你的。
- *听到*：无。四站默认全静音，音频只能在 Esc 菜单里显式打开。
- *感到*：这个房间是静止的、被照亮的、没有第二个东西在动。唯一的动是光里的尘。
- *文案*：H1 `License` · hook `A permit to simply be.` · 按钮 `Stamp it`。按钮在纸的外侧下方，不压在纸上。

**沉浸**
- 一次仪式，内部三段 `verifying → stamping → approved`，实测 **2.8s + 3.6s = 6.4s**（2026-11-19 A1 以 `sites/license/ritual.ts` 为准；旧文档 8–10s 已作废）。用户只按了一次（这是「一个动作」的内部节奏，不是三步任务）。
- **三段怎么画，是这一站最关键的一处产品裁决**：三颗点 + 三个文字标签（`VERIFYING` / `STAMPING` / `APPROVED`）画出来是一条**进度条**，读起来是"你在第 2 步"；杠杆下压 → 印头落纸 → 章留在纸上，读起来是"它正在被批准"。**同一个状态机，形状决定性质。** 三段推进只做站点内的状态机，**不画进度条、不列三步**；只允许一个极小的 `approved` 状态词落在纸面底部（2026-11-19 A1 裁决），完整三个英文标签进 Esc 的 About。
- 仪式结束后**桌面不清空**，纸留着，用户可以继续做三件无意义的事：把光挪一下（光源是画布渐变，拖动就真的会动）、再盖一次章（可以盖歪，歪的章不会被纠正）、把纸角折起来。**这三件事都不产生结果**，它们只让这张桌子是"活的"。
  - "不产生结果"是个负向断言，光说验不了。**可证伪的形式——不变项是"身份"，不是"像素"**：摆弄前后**编号、日期、宣言句三项完全一致**，且**不产生第二个编号、不产生第二个导出入口、不出现任何计数/完成度/解锁**。
  - **画面允许改变，而且必须改变**：盖歪的章留在纸上不被纠正、按 `f` 纸角真的翻起来（三角纸背 + 折痕影）、横向拖拽时光会移动——**这三样正是它们存在的理由**。写成"章的位置必须完全一致"，等于把这一站唯一的手作感禁掉，然后逼工程师去做一个会自动校正的章。
  - **这两半由两把不同的尺分管，别再加第三道目视检查**：前半（身份一致、无第二编号、无计数）**只能人验**——读文本前后比对，进手测协议；后半（必须改变）**已由 STAY 关闭测试机械保证**——`fold = false` 后画面毫无变化就说明那段没在干活。给"必须改变"再加一条目视判据，等于把 A-4 用成第三把尺，重复。
  - 一般化的教训（值得单独记一行）：**负向断言转正向断言时，先问"我要守住的是它的身份还是它的样子"。守样子会把产品里的活东西一起冻死。**
- *慢变量*：晨光带的角度在 4 分钟里单调下移（阳光在走）。振幅小到不会让人"注意到效果"，但两张相隔 3 分钟导出的图并排放，光的位置不同。
- *诚实说明*：仪式给的是**仪式感**（重、准、有反馈），不是**停留**——盖章 900ms、纸飞机 1800ms，加起来不到 3 秒。这一站能做到 90s 停留的唯一依靠是那道光的慢变量 + 两个可摆弄。它的沉浸仍然是四站里最短的。

**带走**
- **主**：一个编号 `EMP-20261118-317`。它不是一句给读者的话，它是个形状——你可以念给它听，也可以只截那一行（屏幕上**可选中**，不靠按钮）。
- **次**：一张 **1410×1000 PNG**（= 屏上纸的比例 1.41 的等比例裁切），含编号、日期、宣言句、右下朱砂印章。导出是**裁切当前帧**（`drawImage` 到离屏），不重渲染也不重排文字——所以图里的光带角度等于**按下 Save 那一刻**屏上的角度，包含用户拖光后的偏移。**产物比例必须与屏上纸一致**：早先写的 720×1000（竖版 0.72）与横版纸不同比例，cover 裁切会把纸的左右各切掉三分之一、右下印章可能落出画外，那等于产物是假的。
- 纸上一行小字：`NO COPY IS KEPT.` —— 这不是免责声明，这是实话，而且在这个语境里它是礼物（没有档案，也就没有人审你）。
- 宣言句（≤ 2 句，不带任何承诺）：`This permit entitles the holder to rest, to stop explaining, and to take up space.`

**零件栈映射**（2 件 + L5 + 一站内仪式层）

**计数口径**：L0–L4 的**真零件**才计入"零件数"，L5 UI（T13）与站内代码都不算——混算会让这个指标注水。

| 层 | 零件 | 在用户体感上负责什么 |
|---|---|---|
| L0 | `paper-ink` 🔄 | **这张纸本身**：纤维、边缘、暗角。它让「盖章」这件事有承重感——盖在空气里是假的，盖在纸上有重量。这一站纸**是主体**（占面积 55–80%、比例 1.41、被盖章的对象、被一道斜光照）。 |
| L4 | `pixel-post` 🔄 | 全场唯一的光学：grain ≤ 0.05、**vignette 8%（✅ 已实现，`pixel-post` 烘进整屏覆盖图）**、无扫描线、无抖动。它把屏幕变成「一张被拍下来的桌面照」。**暗角只由 L4 画，站内的 `morning-light` 不得再叠一层**（§2.2-A-3）。⚠️ **`vignette` 不承担跨站差异**：8% 与 14% 在 L\* 里只差 **0.6–0.8**（`MANUAL-QA §13` 换算），肉眼不可分。这站与 `/still` 的区分靠**色指纹**（L\* 74 vs 26、色相 35° vs 208°、饱和 0.098 vs 0.58）。 |

| — | *站内代码：仪式层（非零件）* | 台账、冲压、纸飞机三个绘制 + 三段时序 + CTA 时机 + `done` 标记。**约 115 行，其中 125 行是现成的**（`sites/license/parts/index.ts`，就在原地，不用搬）。 |
| — | *站内代码：停留层* | `sites/license/stay.ts`（光线角度下移的慢变量 + 拖光，37 行）与 `sites/license/fold.ts`（重盖 + 折角，20 行），两个文件头各一张 `STAY` 开关表供逐件关闭测试。**盖章三段不在其中**——它产出带走物，不是停留。**行数不再设上限**（§0）。 |
| — | *导出* | 0 行新代码：复用 `sites/license/export.ts`。 |

**为什么仪式不进零件**：`Stage` 不给零件实例、`WorldFrame` 只读，**零件 → 站点的反向通道一条都没有**（契约刻意）。**三重封口的完整推理见 HANDOFF 附录 A.2**——最硬的一条是"三段名字必须出字，而文字只能由 L5/站点出"。处置：仪式留站点作用域，`done` 是站点内的 boolean，零契约、零通道、零魔法数字。
→ 代价：这一站是四站里**零件最少（2 件）但站内代码最多（165 行）**的一站，也是唯一没有零件化仪式的一站。它**最快能出画面**（80 行现成），但第二个站若也要"仪式"，这 80 行会复制一遍——**那时才该抽象，现在抽象是给一个用户建模**（§8-4）。

**一处必须避开的返工**：那 125 行里其实是**四个**工厂不是三个，`createPaperPart`（128×128 程序化纸纹 + 双线框）就是 `paper-ink` 要做的东西。**不能一边用 `paper-ink` 一边让站内再画一遍纸**，否则一份纸上画两次纸。正确做法是 **T03 吸收这 30 行**（瓦片生成器 + 双线框做成参数），站内只留台账/冲压/纸飞机。

**不装什么**：不装任何 L2 自走实体（室内飘浮物 = 立刻变成特效演示，BIOME-ASSET-MAP 这条结论我完全同意）、不装 L1、不装麦克风。

### 1.2 `/hug` · field

**一句话定义**：`A dusk meadow where a wish leaves as a link.`

**情绪意图**
> 你想到一个人（可能刚失恋，可能刚生病，可能只是很久没说话）。你在对话框里打了一句，看了两秒，删掉。你想寄一个**不需要回话**的东西过去。

**进入**
- *看到*（2026-11-20 实机口径）：深橄榄草甸，10 株蒲公英形成 5 簇花球，细密绒毛在左上标题对面铺开；右上是一团逆光暖斑，不是圆盘太阳。绒毛随微风轻晃但**不飞走**——它们在等你。
- *听到*：无。
- *感到*：有风，风有方向，风在等一个时机。你不需要马上做任何事。
- *文案*：H1 `Hug` · hook `Send a little warmth as a link.` · 按钮 `Let it go`。
- **按压语义（写死，工程师按这条实现）**：**按画面上任何地方都等于「就是现在，放开它」。** 主按钮只给这个动作一个名字和一个可访问入口，**不是唯一的触发区**。理由不是偷懒，是这一站的构图：地平线压在下 1/3、整片草原就是那个"可以碰的地方"，`Let it go` 是给这件事命名，不是给这件事划界。误触在这站不构成错误——点草地在语义上就是"现在"。
- **但保底不等于主路径**：草地**不得有可点外观**——`cursor` 不变手型、无 hover 高亮、无涟漪预览。视觉上唯一像按钮的仍然只有 `Let it go`。这样"任何地方都能松开"服务的是触屏与急着走的人，而不是把整个页面变成一个巨大的按钮。
  - **护栏落在站点与 CSS，不只落在零件**：`#stage` 上不得出现 `cursor:pointer`，站点不得给 canvas 加 hover 高亮（零件侧加不了——它只读 `WorldFrame`，碰不到 DOM；但**零件也不得自己画 hover 反馈**）。
  - **护栏只针对"视觉招徕"，不针对"可操作性"**：`Let it go` 那个真按钮必须保留、可聚焦、可回车触发。"按哪里都能放开"不是**无障碍路径**——键盘用户只能走按钮。
  - **两条触发路径，都要通**（上一版漏掉的一半）：草地被按 = 站点**转发** `frame.pointer.down`（零件自触发）；`Let it go` 被点 = 站点**注入** `stage.setPointer`（按钮在 canvas 之外，不注入就什么都不会发生）。**不招徕 ≠ 不响应。**
  - **a11y 在这里是结构性保证，不是善意**（评审时这两者分量完全不同）：注入绑 `click`，而 `click` 覆盖回车/空格 → **键盘用户走的正是注入这条路，因此删掉真按钮 = 删掉键盘唯一的路径 = 功能故障**。它不是"我们承诺保留按钮"，是"按钮没了键盘就没法用"。
  - **UI 事件不得混进来**：点 Esc 菜单不能把蒲公英放飞（见 §2.3）。这一站是**不可逆**的，一次误放飞就把仪式毁掉。
- 首屏**不出现** `Use mic` / `Share` / `Send one on`——麦克风在 Esc 里，分享只在种子离场后出现。

**沉浸**
- 蒲公英三状态机 `ready → drifting → away`，绒毛错峰脱落（沿用 `meadow.ts` 的 `DETACH_SECONDS`）。
- *慢变量*：花球绒毛随 `uTime` 轻晃；逆光保持常亮。当前实现不做太阳升落、也不旋转风向——这两条是旧 Canvas2D 方案的设计意图，未在 `hug-meadow` 里实现，别按旧文验收。
- 用户可以**一直待在"还没放飞"里**——绒毛会随风晃，不会催他。多数人会等一阵看起来更"对"的风再松手。这把停留变成了仪式，而不是等待。

**带走**
- **主**：一条链接 `?from=hug`。贴进任何对话框，对方不用注册就能打开。
- 打开后看到的是新的一株蒲公英，和一句话：`Someone sent you this link. You can send one on.`——**这句话是真的**：URL 里有 `from`，所以「有人寄了这条链接」是链接本身证明的事实。但**不说**「有人回赠了你」，因为我们不可能知道。
- **次**：一句可复制的短句（本地模板，无 PII）。

**零件栈映射（当前，2026-11-20）**

| 层 | 零件 | 在用户体感上负责什么 |
|---|---|---|
| L1 | `hug-meadow` ✅ `world` | 整片草甸：10 株 / 1,335 颗种子的 three 场景，背景、雾、逆光、花茎叶与放飞全在这一件里。不透明铺满，L0 空缺。 |
| L5 | UI | 标题、`Let it go`、带走、Esc。 |

**2026-11-20 修订**：早前“`/hug` 是纯 Canvas2D 站、L1 永久空缺”的裁决已推翻。用户要求对齐原站 `dandelion-meadow` 的实机效果；近似版（`field-ground` + `dandelion` + `boids` + `sun` + `pixel-post`）被明确否定。现在按原站 chunk 完整还原为单一 `hug-meadow` L1，旧五件套从栈里移除，源码仍留在仓库供 preview/golden-run 使用。

**不装什么**：不装 `voxel-world`——草甸不是体素海，不需要第二个介质。不叠 `wind-grass` / `fireflies`（两套自走实体抢同一层注意力，画面会脏）。

### 1.3 `/still` · tide

**一句话定义**：`Water you can sit under, and leave a line behind.`

**情绪意图**
> 你今天已经把三个页面开了又关。任何要求你选择、回答、勾选的东西，你都在两秒内关掉了。你不想要一个能做的事，你想要一个**不需要你做任何事**的地方。

**进入**
- *看到*：满幅的水。没有地平线、没有岸、没有边框、没有中心物体。水在极缓慢地变暗。H1 压在水面上。
- *听到*：无（若用户显式开声音，是闷的水下低频——但默认关）。
- *感到*：你在水里，而且没有被要求浮上来。
- *文案*：H1 `Still` · hook `Nothing here needs an answer.` · 按钮 `Sit`。

**沉浸**
- 按下 `Sit`，两档给同一个语义（**光从你上方经过**）但两种画法：有 webgpu 时镜头真的下潜到水位线以下一个身位，上方出现折射光带；无 webgpu 时改为**连续的上亮下暗 + 雾 + 微粒**——**无圆斑、无焦散**。
- *慢变量*：光的亮度与角度在 4 分钟内**单调递减**，像日落从水面退走（有 gpu 档是那条光带，无 gpu 档是**上亮下暗的连续梯度**在暗下去）。
- 之后**什么都不用按**。这一站是四站里唯一没有第二个动作的：气泡自己往上走，光自己暗下去。用户随时可以走，走的时候没有"未完成"。
- 这是全站最便宜也最有效的停留机制——人会不自觉等"光再暗一点"。

**带走**
- **主**（也是唯一）：一段可复制的英文短句。**不含任何数字**——没有时长、没有米数、没有百分比、没有"你待了 X 分钟"。（主理人已裁决，我同意并加固：一旦出现时长，这一站立刻滑向「今天比昨天多坐了两分钟」的进步曲线，那就变成打卡。）
- 句子由**光的状态**决定，五档，所以同一 URL 在不同时间打开给不同句子——回访理由靠这个，不靠时长：
  `The light is still on the water.` → `The light is leaving the surface.` → `The light is thinner than when you sat down.` → `The light is almost under.` → **`The light is gone. The water is still here.`**（最后一句是全站的落点，不要改）

- 停留 **≥ 40s（从坐下起算）** 才出现带走入口：因为「坐着」不产生事件，需要一个门槛证明你真的坐过；`/koi` 同样按 40s 给 `Keep this frame`，但计时从页面打开起算。**这个阈值只决定"什么时候给你"，不进产物。**
- **刻意只给一种载体**。给它第二件（一张卡、一个链接）等于给它一个奖励，而这一站的全部意义是「这里没有奖励」。理由见 §5-E。

**零件栈映射**（声明 **4 件** + L5；单机实装 3 或 4 件）

`/still` 的 L0 **常驻**，L1 按能力在场或不在场（§5-H 有架构理由）。所以"声明栈"是 4 件，"这台机器上实际装了几件"是 3 或 4——两个数都要说清楚，别混。**任何时刻画面里只有一层水**：有 L1 时 L0 在像素上被它整块盖住（0 像素，不是"少了一层"），无 L1 时 L0 就是那层水。

| 层 | 零件 | 在用户体感上负责什么 |
|---|---|---|
| L0 | tide 水底材 🔄 **（常驻）** | **无 webgpu 时它就是整幅水**：深水色阶、焦散、悬浮微粒、水下雾，这一档里它是骨架不是装饰。有 webgpu 时它被水体盖住，焦散与光柱由 voxel 世界的自带水体承担——被遮挡是设计，**所以 L0 只能是骨架/底，要有可见的膜它必须是 L2**（P2，§5-H）。 |
| L1 | `voxel-world` ✅ `gl` **（有 webgpu 时在场）** | **一个地方**：可下潜的水体、海床、海藻、光柱、水雾。不支持 webgpu 时装配器跳过并记 `unsupported`，`/still` 退回"一片水"。 |
| L2 | `bubbles` 🔄 `screen` | 两档**都有**的动：气泡从下面上来，不受你控制。它也是两档之间唯一的连续性——哪一档看到的都是"有东西在往上走"。 |
| L4 | `pixel-post` 🔄 | 水下介质：偏青的 grain 0.03 + vignette **14%**（**✅ 已实现**）。**无抖动**（全局抖动已删，§2.2-D）。⚠️ **"水压感"不能只靠 14% 暗角**——它和 8% 只差 0.6 L\*。水压感由三样共同承担：**偏青 grain + `glow` 的上亮下暗 + 14% 暗角（常量）**。 |
| L5 | UI（✅ 已完成） | 出字、按钮、带走入口、Esc。 |
| — | *站内代码（非零件）* | `Sit` 的状态切换与水位线（约 40 行）。**有 L1 时是镜头下潜，无 L1 时是上亮下暗的连续梯度 + 雾**——同一个语义（光从你上方经过），两种画法。 |

**不装什么**：**不装 `blow-input`**（主理人已裁决，见 §5-B）。不装 ASCII 鱼（BIOME-ASSET-MAP：「抽象水」和「ASCII 水族箱」二选一，不要叠）。

**L0 定稿形态（三版并排的结论）**：选 **A 方向**（`dist/preview/tide-a.html`）。实测 L\* P50 **26.1**、色相 **208°**、上/下半差 **+6.7**（光从上来）、动态范围 **26.9**——四站里唯一"暗、冷、且有纵深"的一版。
  **注**：A（`tide-a`）是三版并排时的**历史候选**，用于确认"暗、冷、有纵深"这个方向；**定稿 ≠ A**——定稿删除了全部圆斑，改为连续衰减 + 雾 + 微粒（见下文）。别照 A 去改。
- **一处必须改：光的形态。** 现在是约 15 个直径 120–260px 的大软盘，软边≈直径的 100%，所以读成"云"。
- **判据（已定，字段改名 `caustic`→`glow` 之后重定）**：旧三条（数量 40–80 / 直径 ≤8% 画幅宽 / 软边 ≤直径 25%）**作废**——那是**焦散**的规格（小而密、边硬，像海床上的光网），而**无 gpu 档没有海床**；套上去就是做一堆小硬点，等于又在无海床的档里模拟海床。
  实测 `tide-a` 亮像素按高度十分位 `13/27/18/10/20/17/11/0.2/0.2/2.3`：**前 70% 大致均匀、有回升**。所以真缺陷不是"太大太软"，是**"没有和任何表面发生关系"**——上不下来、下不衰减、不锚定水面。
  ⚠️ **先纠一个设计错误：`glow` 不能用"一个个圆斑"来表达。** `tide-v2` 里有约 40 个柔圆盘，看着像**大光圈背景（bokeh）**——而**圆斑本身就是"可指认的物体"，直接违反 S2「中心 60% 内零实体」**。我此前五条判据全在测"斑的分布/大小/软硬"，没有一条去和 S2 互检；所以每一轮数字都过、画面都错。
  **改法**：`glow` 用**连续纵向衰减 + 雾 + 微粒**表达光，**不产生任何可数的圆形**。光靠"顶部更亮、越往下越暗、雾越厚"被感知，而不是靠"几个亮点"。

  **五条判据（1 方向 / 2 可见度 / 3 无实体 / 4 整片 / 5 软边）**：

  | # | 判据 | 管什么 | 口径 |
  |---|---|---|---|
  | 1 | 十分位**均值单调下降**（不要求"亮像素占比"） | 方向 | 上→下逐段递减，无回升 |
  | 2 | **顶部 20% 与中部 60% 的亮度差 ≥ 8 L\*** | **可见度**（不用"斑块局部差"，因为我们不许有斑块） | 两条横带的均值差 |
  | 3 | **零实体**：中心 60% 区域内**没有任何可指认的闭合亮形**（与 S2 同一条判据） | **形状** | 目视 + 亮区连通域数 ≤ 3 |
  | 4 | **P95−P50 ≤ 16 L\***（放宽） | **只防"整片发亮"** | 全帧分位差 |
  | 5 | **P99 梯度 ≤ 0.6 L\*/px** | 软边（不是硬轮廓） | 逐像素梯度模 |

  **为什么这样改（三条原判据测的是同一件事，而"看得见"没人测）**：原 1（单调）、2（顶部亮区占比 ≥60%）、4b（上下四分位比 ≥3）**都在测"垂直衰减"**——一旦单调成立，2 和 4b 自动成立，等于一条判据测了三遍。而真正决定画面有没有光的"**光斑亮不亮**"，四条里一条都没有。所以 `tide-final` 4/4 全过、画面却没有光斑：**判据把"分布对了"当成了"光有了"。**
  **`P95−P50` 是错的量**：这张画本身有 16 L\* 的垂直梯度（35.7→19.7），梯度本身就贡献了 P95−P50。它是**"全局分位统计"**，在带全局梯度的画面上必然把梯度算进去——**要测局部事件，就必须局部化**（判据 2）。
- **B 版作废**：色相 187°（偏绿，出 `/still` 的 195–225 带），且细长光丝读成**划痕**——那是"破损材质"，不是光。
- **C 版留档不定稿**：饱和度 0.211（近灰）、动态范围 9.2。它"信息量低"是对的，但**L0 本来就不该有信息量**（那是气泡与慢变量的活）；C 的真正问题是它连"水"都不像，不是它太安静。**减法对照的结论是：光该留，但要"可见而柔软"（现在的判据 2 + 5），不是"小而硬"。**
- 这三版都是 **L0-only**（`drawn 1/1`），没有气泡、没有冲印。**不要用 L0 单层的观感去判这站的信息量。**

**两档的验收：四条硬不变；视觉等价**不是承诺**。**

- **硬不变（截图可查）**：H1 与按钮位置、构图主轴（满幅／无轴／无边框）、慢变量（光 4 分钟单调衰减）、带走物（同一套五档句子）。
- **不承诺两档看起来一样。**两条补偿都撤了（`vignette→18%` 破 §2.2-A-3 上限；`bubbles` 增密有构造顺序悖论），**理由见 HANDOFF 附录 A.1**。两档各是一幅完整画面：有 L1 时"一个地方"，无 L1 时"一片水"，都是这一站的产品形态，不是主次。
- **"用户不应该知道少了东西"这句已删**——他会知道，这没问题；他不知道的只是"本来还能有什么"。
- **L0 的定位必须连着说**：被遮挡是设计（有 L1 时 L0 是 0 像素），**所以 L0 只能是骨架/底，要有可见的膜它必须是 L2**（P2 纯加法）。
- ⚠️ **P2 **不会**解除 L0 的遮挡（我上一轮推错了，这里更正）**：「被盖住」有两个前提，P2 只拆掉其中一个——
  | | 是什么 | P2 之后 |
  |---|---|---|
  | **DOM 层序错误** | `#gl` 排在 `#stage` 之后 → 整个 2D 画布被压在 GL 下面（L0–L5 全遭殃） | **修好** |
  | **像素遮挡** | L0 在**层序里**本来就在 L1 之下；GL 后画且不透明 → L0 仍是 0 像素 | **不变** |

  `voxel-world` 自己声明 `blend:'source-over'`，`glBlend` 缺省取它 → **完全不透明**。所以 P2 之后 L0 仍然被遮挡（这是层序被**正确执行**，不是 bug），「两档各 3 件」不用重判、§5-H 不用重写。
  **若要 L0 可见，只能把 GL 的合成模式改成 `screen`/`lighter`——但别这么做**：`screen` 会抬黑位，而 `/still` 的明度带是 **L 8–15（四站最低，且四条带不许重叠）**，很可能直接把这一站挤出自己的带。那是拿"沉没成本换判据违规"。
  **降级事实句（若 `compositeGl` 实机测不到就按此写死）**：`/still` 的后处理**只作用于 2D 层**；海床、鱼、水体、光柱**不参与冲印**。原因是「**测不到，不是不想做**」——宁可写"未测"，不许估一个数。判据：compositeGl 实测 **≤3ms** 才允许接 P2 路径，超了就走 fallback，不要"再优化一下试试"。口径按 dpr² 走（1 Mpx ≈0.35ms，4 Mpx ≈1.4ms）。
  **改成可测，不要继续推理**（判据见 `MANUAL-QA` S3b）：同一 `(seed, t)` 出两张图——装 L0 / 不装 L0，**默认配置下必须逐像素相同**（每通道 ≤1）。出现可辨差异，才说明 L0 真的漏出来了。

### 1.4 `/koi` · ink / paint / real

**一句话定义**：`A working koi pond you can touch, in ink, watercolour, or real water.`

**情绪意图**
> 你不想被安慰，也不想解决任何事。你想让眼睛有个地方停着。你需要一块**在动但不需要你**的东西；如果愿意，也可以伸手碰一下水面。

**进入**
- *看到*：俯视一方真锦鲤池，默认是宣纸水墨。纸白、墨鱼、浮萍、落叶；右下角有池边莲叶。它不是字符画，是 zz85 原作的 three.js 水体：`real` 有池底卵石、焦散、折射和鱼影，`paint` 有 pigment 晕染和纸纹，`ink` 有墨扩散与鱼尾拖墨。
- *听到*：默认静音；Sound 打开后有程序化水声、低频池水与鱼群声，Music 另有 Still / Flow 两档。
- *感到*：慢、安静、有纵深。三种 look 不是滤镜，是三条不同的渲染路径——同一条鱼在 ink 里是墨块，在 paint 里是水彩，在 real 里是带鳞光的锦鲤。
- *文案*：H1 `Koi Pond` · hook `Watch the fish. That is all.` · 主按钮 **无**。

**沉浸与交互**
- 鱼群会整体换向、浮萍漂移、落叶下沉、水面有风纹和鱼尾涟漪。
- 指针划过水面：`Ripple` 推开鱼、`Feed` 撒食、`Call` 按住聚鱼；三种模式都来自原作。
- 相机：`Top` 正俯视、`2.5D` 斜看池底、`Orbit` 缓慢绕池；双指/右键也能转。
- 池底：`Pebble` 卵石、`Sky` 浅蓝灰泥、`Dark` 深色池膜；天气：`Dry` / `Drizzle` / `Rain`。
- 设备倾斜/摇晃可开关（`?motion=1`）；移动端自动 9 条鱼，桌面 11 条，降档 7 条。

**首屏边界**
- 首屏只有 H1 / hook / 池塘。**没有主按钮，没有导出按钮，没有风格切换器直接露在首屏**。

**零件栈**
| 层 | 零件 | 负责什么 |
|---|---|---|
| L0 | `paper-ink` | 纸底。`/koi` 不画纸边框，整屏就是池面；WebGL 不可用时它兜底成纸。 |
| L1 | `koi-pond` | 完整 three.js 锦鲤池：三风格、三相机、三池底、三档雨、触摸、音频、鱼/浮萍/落叶/涟漪。 |

### 2.2 三处最容易滑坡的地方（A 的四条保留；B 的数量护栏、C 的雷同护栏已撤）

#### A. 「多种效果叠加」→「特效演示」

**具体形态**：观众一眼能数出三个独立效果——"那边有气泡、那边有鸟、那层有扫描线"。每一件都在争取被看见，于是互相抢；用户记住的是效果，不是地方。

**为什么危险**：用户的原话是「组合，多种效果叠加」有两种读法，差一个字的距离，产品差别一个数量级——**叠加** = 多个零件共同解释**一个物理现场**，效果数量在体感上不可数；**演示** = 多个效果并置展示，效果数量就是卖点。

**判断标准（我给的唯一一条）**：
> 每站必须先声明**一个物理前提**（一条光方向 + 一个介质 + 一个风/流方向）。任何零件，如果不能用这个前提解释成"它的后果"，就不得进站。

按这条标准验四站：`/license` 光从左上斜下、介质是空气与纸、无风 → 纸纤维、尘的浮动、章下的阴影全是同一束光的后果；`/hug` 太阳极低、介质是空气、风单向 → 草倒向同一边、绒毛上飘而横移、飞虫被风推着走；`/still` 光从水面下来、介质是水、流向上 → 气泡、加到 14% 的 vignette，以及**该档位里的那一层水**（有 gpu 档是光柱，无 gpu 档是连续上亮下暗 + 雾 + 微粒，无圆斑无焦散）都是"水压在屏幕上"；`/koi` 光从上方平铺、介质是纸与浅水、无风 → ink/paint 的墨只散不飘；切到 real 后同一束光变成水下折射、池底焦散和鱼影。**三种 look 是三条物理路径，不是滤镜**；四站仍成立。

**四条硬护栏**：

1. **可数性测试**（人工，30 秒）。把首屏截图给一个没看过本文的人，问「画面里有几个效果？」。若他能列出 ≥ 3 个互相独立的"东西"，判为特效演示，退回重做。他只能说出一处地方 + 一个动作入口，才算过。
2. **零件职责表**。每个零件在 §1 里必须有一句「它负责什么」。**两个零件不得负责同一件事**——`dandelion` 是前景实体（有叙事），`boids` 是远景群体（无叙事），这两句不能互换；若互换后不觉得错，就是重复，删一个。
3. **颗粒必须是"动的"**：grain 要按 `floor(t × 24Hz)` 循环换相（预烘 ≥4 张 tile），**不许烘成一张固定贴图**。理由不是洁癖——**静止的噪点读成"屏幕上的脏点"，动起来才读成"胶片"**，人眼会锁住固定图案。
   ⚠️ 顺序约束：**先把"动能颗粒"搬进快路径，再删读回路径**（读回路径是当时唯一实现了 24Hz 换相的地方）。反过来做，会先删掉唯一在动的颗粒、然后以为"预算省了、画面没变"——画面变了，只是那一帧看不出。验收见 `MANUAL-QA` **G9**（间隔 ≥1/24s 两帧的像素差中位 ≥0.5 L\*；静态贴图给出 0）。
4. **L4 强度上限**：grain alpha ≤ 0.05 / vignette ≤ 14% / 扫描线 ≤ 0.08（仅 high LOD）/ ~~抖动只允许在 `/koi` 全局开出~~（**抖动已删，见 §2.2-D**）。超过就是"滤镜演示"。
   **暗角只由 L4 画，站点不得自己再画一个**——`/license` 的 `morning-light` 已经画了一层，再叠 L4 的暗角就是两层，边缘会脏。两者只能留一处，**留 L4**（它整场唯一、可统一调）。
   ✅ **已实现**：`pixel-post/index.ts` 的 `PixelPostOptions` / `DEFAULTS` / `normalize()` 均含 `vignette`，默认 8%、硬夹 ≤0.14，烘进快路径的整屏覆盖图。它曾缺失数月而无人发现——"关掉它看有没有变化"与 `MANUAL-QA` G12 就是为这类失效准备的。
5. **关掉一件也要成立**。逐件关闭后截图对比，差异必须能用一句话指出「哪里变了」。指不出来 = 无效零件，删。

#### B. 「复合装配」→「什么都堆上去」

**具体形态**：既然能叠，就把每层的每一个零件都开上。页面装 8 件，首屏拥挤，帧率掉，降级到 low 之后最重要的那件被挂起。

**硬护栏**：

1. **同层不得有两件承担同一职责**。多件可以（HANDOFF 层序允许），但必须一前景一远景、一有叙事一无叙事。`dandelion` 是前景实体（有叙事），`boids` 是远景群体（无叙事）——这两句不能互换；若互换后不觉得错，就是重复，删一个。
2. **一个介质，不是两个**。这是最容易犯又最难看的一处：`/hug` 若同时装 `field-ground`（草原）与 `voxel-world`（海洋世界）就是**两个介质**，禁止（见 §5-A）。`/still` 是同一条规则的另一种形态——**同一个水只有一份"可见的体"**：有 webgpu 时水体的体量归 `voxel-world`，L0 水底材照常装配但被它整块盖住（0 像素）；无 webgpu 时 L0 就是那层水。L0 为什么不摘掉：`stage.ts` 的帧循环从不 `clearRect`，全靠有件不透明底材每帧铺满画布，摘掉会留残影并多一次全屏清屏（§5-H）。
3. **`expendable` 只允许给最不重要的那件**。降级时被挂起的必须是用户说不出名字的那一件。

**原第 1、2 条已撤（2026-11-19）**：单站零件硬上限 = 5、进一件出一件。原因是主理人要求「无上限，不断叠加补充」——这两条正是压住叠加的闸门。

#### C. 「零件复用」→「同一套东西换皮」

**具体形态**：四站看起来像同一个模板换了四套配色。用户点开第二个站会觉得"来过了"，产品从四个房间退化成一个主题商店。

**护栏：已撤（2026-11-19，主理人裁决）。**

原四条——「复用只允许发生在 L4 与 L5」「`paper-ink` 是唯一例外」「四站必须通过 §3 的七条判据」「降级路径不得把两站拉成一样」——一并删除。**零件可以跨站任意复用，两站可以长得像。**

§3 的七条判据保留，但性质变了：它是**想查雷同时的工具**，不再是对抗式验收门。原「L0 底材复用规则」一节随本条一并删除（见 git 历史）。

#### D. 零件的"声明存在、实际失效"——三种形态与处置（可复用）

本轮抓到五例：`manifest.bytes`、`engine` 字段、`lead` 字段、`without` 字段、`dither`/`vignette`。它们的处置**不一样**，用一个判据分：

> **夹住之后效果还在（只是变弱）→ 夹；效果根本不存在 → 删。**

| 情形 | 处置 | 为什么 |
|---|---|---|
| 效果的触发条件与合成链**互斥**（任何站都不会触发） | **删掉这个选项** | 留着一个永远不发生的声明，等于留一个会被人相信的谎。`dither` 属此类：它抖 `alpha<255`，而合成链终点是不透明整帧——不是"这一站不触发"，是"任何站都不可能触发"。**而且它不免费**：开着它强迫走读回路径（实测 5.1ms），把 `/koi` 顶到降档、LOD low 下格子变粗，正好糊掉它唯一的内容。 |
| 参数**越界但有效果** | **夹住 + 报一行"被夹自 x→y"** | 效果还是真的，只是弱了。夹是可接受的处理 |
| 参数合法、但**在某站的栈里命中率 0** | **门输出一行 + 拒绝该站配置** | 需要离线装置复现该站的合成链 |
| 效果**本可以存在**，只是没实现 | **实现它**，别删 | `vignette` 属此类：快路径天生适合烘一次径向渐变，两站气质都押在它上面 |

**零消费者的选项要和"失效"一起查**：`blockPx` 目前四站规格里没有一站用，而**整条读回路径（5ms）只为它存在**。判定同上——要么给某一站找到真实用途，要么删。**产品侧结论：四站都不需要"像素块化"**；若将来某站需要，那是一件新零件，不是一个睡着的选项。

### 2.3 输入与产物的红线

- **零输入框**，四站全零。最容易加、也最该拒绝的一个功能是「在许可证上输入你的名字」——不做。
- **UI 上的指针事件不得进入世界**（产品级 bug 的护栏）：`host.ts:199` 的 `window.addEventListener('pointerdown')` 是**无条件**的，所以点 Esc 菜单里的 `Sound` / `Quality` / `Close`，`pointerdown` 会冒泡成 `frame.pointer.down` = true。后果按站不同：`/hug` **想关静音的人会把蒲公英放飞**（`ready → drifting → away` 不可逆，仪式被 UI 操作毁掉）；`/koi` 会在菜单后面按下一团墨，而墨**不回到原状**，错误永久留在画面上；`/still` 不受影响（它没有第二个动作）。
  - 修法分两半，**缺一半就把主按钮变成假的**：① **世界只接收「画布上的」指针**——`event.target !== canvas` 一律不转发（菜单、按钮、文字都在 canvas 之外）；② **UI 元素若要引起世界变化，由站点显式调用 `stage.setPointer` 表达**，并且必须能自证"这一次是一个决定"。`setPointer` 本来就是 `Stage` 的公开 API，所以这是**用现有接口**，不开新通道、不动契约。
  - ② 必须绑 `click` 而不是 `pointerdown`：`click` 覆盖键盘回车/空格，于是**键盘用户走的正是注入这条路**——删掉真按钮就等于删掉键盘唯一的路径。这条比在文案里写"必须保留"更硬，它是技术性的。
  - 必配断言：**「Esc 菜单打开时合成一个 `pointerdown`，`frame.pointer.down` 不得出现上升沿」**。`stage-smoke` 测不了（没 DOM），落在浏览器门或宿主单测；两条都还没有时，**至少写进手测协议，不能只停在"我们知道"**。
  - 法则（原文进 HANDOFF A.3）：**站点是 UI 意图与世界事件之间唯一的翻译层。** 世界只接收"画布上的"指针，UI 与世界的输入边界由站点守。
  - **四站里只有一站需要注入**——这个比例本身就是设计对的证据：**默认不翻译，只在 UI 真的驱动世界时翻译一次**。

| 站 | 世界接收什么 | 需要注入吗 |
|---|---|---|
| `/license` | 什么都不接收：盖章因果整件在站点 | **否**（没有"按画布响应世界"的零件） |
| `/hug` | 草地按下 = 决定（转发）；`Let it go` = 决定（注入） | **是**（全四站唯一一处） |
| `/koi` | 连续场位置，无"决定"语义 | **否**——注入会凭空造出一个决定，且**墨单向不还原**，点一下按钮池面上就永久多一团墨 |
| `/still` | `Sit` 之后没有第二个动作 | **否** |
- **麦克风**是本期唯一的敏感输入，规则写死：默认**关**，只在 Esc 里显式打开、随时可关；只取 `frame.audio.level` / `bands`（stage 级注入），**不录制、不缓存、不传输**；关掉后 `blow-input` 退化为指针驱动（按住 = 等风），功能不缺失；页面上不出现「我们听到了你」这类暗示（我们只取了一个音量数字）。
- **每一句声称必须有本地可验证的来源**（这条是文案的第一性规则，其他都是从它推出来的）：页面说的每件事，都要能在浏览器里指出是谁在作证。做不到的句子，不管多暖，都不写。
  - 允许：`Someone sent you this link.` —— **URL 里有 `from`，是链接自己在证明**，不是我们编的（这条是四站里唯一的"关系句"，它能成立纯属 URL 的功劳）。
  - 允许：`NO COPY IS KEPT.` —— 我们的实现事实，可读代码验证。
  - 允许：`The light is gone. The water is still here.` —— 我们自己渲染的光，说什么是什么。
  - 禁止：`Someone sent a hug back.` / `12 people are here right now.` / `Delivered.` / `A stranger saved this for you.` —— 零服务端意味着我们**不可能知道**有没有人回赠、有没有送达、有没有人在。
  - `content/*.ts` 是**未迁移的旧文案源**，被站点 TS 文件 import 但**不进构建产物**；`site-build` 与产物文案以 `shared/sites/copy.mjs` 为唯一来源（已兑付终稿）。两套源并存现状见 [`COPY-SITES.md`](./COPY-SITES.md) §5；**不要为了对齐门去删 content/**。

## 3. 四站之间差异的可判定标准（工具箱，不是门）

**这一节是「想查差异时怎么查」的工具箱，不是验收门**（2026-11-19 撤销对抗式验收，见 §2.2-C）。每条都能拿四张首屏截图对照检查，但**四站长得像不再判失败**——它只告诉你差在哪。

### 3.1 七条判据

| # | 判据 | 四站取值（必须两两不同） | 怎么查 |
|---|---|---|---|
| **A** | **构图主轴** | `/license` 中心·平面（正矩形、无纵深）· `/hug` 低位水平线（地平线在下 1/3）· `/still` 无轴·满幅（无地平线/无中心/无边框）· `/koi` 对角（水纹与鱼同一斜向） | 四张首屏截图并排，问「有没有两张的主轴相同」。有一条水平线出现在 `/koi`，就废。 |
| **B** | **画幅色指纹**：全帧 L\* P50 + 色相 P50 + 饱和度 P50 | `/still` L 14–28 / 色相 195–225 / 饱和 ≥0.45 · `/hug` L 26–40 / 色相 35–55 / 饱和 ≥0.35 · `/license` L 68–85 / 色相 25–45 / 饱和 ≥0.12 · `/koi` L 72–86 / 近无彩 饱和 ≤0.10 | 截全帧（避开调试条）算三个中位数。**不用单一亮度区分四站**：`/license` 与 `/koi` 都亮（纸），靠**暖/无彩**分开；`/still` 与 `/hug` 都暗，靠**冷/暖**分开。⚠️ 前两版都写错了："取中心 60%"在 `/license` 上取到纸（L\* 82.6）会误判不过；"背景 P50 四条带不重叠"在实测里站不住——`/license` 的"背景"只是一圈桌边（L\* 20.6），与 `/still` 整幅水重叠。**改过两次的判据要写清为什么改**，否则下一个人会按旧版优化 |
| **C** | **中心是否存在可指认的实体** | `/license` 单一大实体（一张纸，占面积 55–80%）· `/hug` 一个前景实体 + 远景群体 · `/still` **零实体** · `/koi` 多个同质实体（几条鱼，地位平等） | 指着画面中心问「这里有什么」。四个答案是四种不同类别。 |
| **D** | **慢变量类型** | `/license` 光的角度下移 · `/hug` 太阳高度角下降 + 风向旋转 · `/still` 光带亮度单调衰减 · `/koi` 水纹相位 + 鱼群换向 | 站 60s 不动，看什么在变。四站必须是四种不同的东西在变。 |
| **E** | **交互类别** | `/license` 一次性仪式（按一次，之后可以无意义地摆弄）· `/hug` 等一个自然事件（等风）· `/still` **零动作**（按一次坐下，之后什么都不按）· `/koi` 随手触碰（划一下，不需坚持） | 四站各站 120s，数「用户必须做的动作数」：1+摆弄 / 1+等待 / 1 / 0–N 次随手。**不允许两站都是"按住不放"**（这正是 `/still` 不装 `blow-input` 的原因，§5-B）。 |
| **F** | **主带走物载体** | `/license` 编号 · `/hug` 链接 · `/still` 文本 · `/koi` 图像 | 四个产物并排看：一个形状、一段 URL、一句话、一张图。**不许有两站的主产物都是图**。 |
| **G** | **首屏三层元素的具体取值** | H1：`License` / `Hug` / `Still` / `Koi Pond`；按钮：`Stamp it` / `Let it go` / `Sit` / `Watch` | 四个主按钮的动词不得重复，且没有一个叫 `Enter` / `Start` / `Explore` / `Begin`。 |

### 3.2 判定流程（十五分钟，一个人能做完）

1. 四站各截一张首屏（1280×800，`prefers-reduced-motion: no-preference`，不 hover，不动鼠标）。**并排贴在一张纸上。**
2. 查 A：主轴有没有重复。
3. 查 B：四条明度带有没有重叠（工具算，不靠眼睛）。
4. 查 C：中心实体类别有没有重复。
5. 各站录 90 秒屏幕，查 D（什么在变）与 E（要按几次）。
6. 各站导出一份产物，并排看，查 F（载体是否两两不同）与「能不能脱站存在」（PNG 存本地打开 / URL 换浏览器打开 / 文本粘进记事本）。
7. 把四张产物缩到 200px 高排成一行：**看不出是同一个机构发的** → 视觉系统失败；**看不出是四个不同的地方** → 世界区分失败。两个都要满足。

### 3.3 一条差异清单（出现说明「四站同质」，不扣分）

- 四站都用了同一套暗角参数（L4 参数必须至少两项不同）。
- 四站的 H1 都居中在同一垂直位置（`/hug` 的 H1 应该跟着地平线偏下，`/koi` 应该偏左上以让开对角）。
- 任意两站都出现了"漂浮的小圆点"。
- 任意两站的带走入口出现在同一个时间点（`/license` 是仪式完成、`/hug` 是种子离场、`/still` 是坐下后 40s、`/koi` 是打开后 40s——四种触发，但后两者阈值同为 40s，是已知同质风险）。
- 四站的 Esc 菜单文案不同（菜单必须一致——那是"机构"，不是"地方"）。

### 3.4 判据打架时怎么裁

几组判据会互相顶（`/hug` 要保住低位水平线，H1 就得压到画面下 1/3，跟"标题居中"的可读习惯冲突）。优先级固定为 **A > F > D > B > C > E > G**：主轴最不可让，按钮词最可让。**原「一条不达标可以上线、两条不达标回来找我」已撤**：判据不再阻断发布，它只在你**想知道**两站长什么样的时候给答案。

## 6. 诚实边界（不可测、不声称）

1. **不声称任何疗愈效果。** "减轻焦虑""帮助入睡""缓解压力"全部不写。没有前测后测、没有问卷、没有对照，这类表述是不可验证的健康声明，也是一个法律问题。四个站的文案只描述**这个页面里发生的事**（一张纸被盖章了、一行字被复制走了），不描述**你身上发生的事**。
2. **不可测的东西**（写在这里，防止后人假装测过）：留存 / 回访率（无账号、禁跨会话计数）；跨站行为（无共享标识）；情绪改善（无对照组）；真实停留分布（单页应用，无 pageview 序列）；分享链路的命中（无服务端，不知道链接有没有被点开）。
3. **本期唯一可用的验证手段**：构建期断言（网络符号 0 / CJK 0 / 跨站链接 0 / 首屏三层 / 零件数与层序）+ 人工目验（§3 的七条判据）+ **[`MANUAL-QA.md`](./MANUAL-QA.md)** 的手测协议（每站 3 分钟、65 个二值项、四站 ≤40 分钟）。**仅此而已，不要编第五种。**
4. **写约束时按顺序自问四句（顺序有讲究：最便宜的排最前）**：

   | # | 问 | 用什么答 | 需要产品判断力吗 |
   |---|---|---|---|
   | **0** | **用户还缺这一样东西吗** | **开/关对照**（装上、再关掉，两张图/两次交互的差异能不能用一句话说出"用户少了什么"） | ❌ 机器答 |
   | 1 | 契约里有通道吗 | 读 `Stage` / `WorldFrame` 的接口——没有就是没有 | ❌ 读接口 |
   | 2 | 这句有机制能证伪吗 | 判据两样本：一个**必须红**的反例 + 一个**必须绿**的正常图 | ❌ 判据自答 |
   | 3 | 那个机制守住的是**身份**还是**样子** | 看它会不会把"盖歪""颗粒动"这类活东西冻死 | ❌ 看反例 |

   **第 0 问必须用机器答，不能靠讨论**——否则它和"中心没有可指认的物体"是同一个毛病：问五个人三种答案。`dither` 用这一问 5 分钟判死（关掉它，两张图逐像素相同——因为它从未执行）。**它排最前，因为最便宜。**
   **四句里只有第 3 句需要判断力，其余三句都是可执行的检查**——这是本轮最值得留下的一句。

   **④b 这个量会不会被无关因素影响？会，就说明那个因素没有被显式写进算法——把它写进去。** 本轮五例同一个病：bbox 用绝对亮度阈值（**没把"背景"写进算法**）、暗角用角/中比值（**没把"分母≈0"写进算法**）、周期性用短 lag 自相关（**没把"平滑度"写进算法**）、"草不在天上"照蓝天空调色（**没把"天空会变色"写进算法**）、饱和度两个公式（**没把"要的是纯度还是明度"写进算法**）。
   → **不是"别用绝对量"，而是"把影响因素变成算法的一部分"**：相对背景阈值、去趋势、HSV 而非 HSL、与左右邻域比而非与固定色比。
   **还有一句阿基米德点**：**这条约束被违反时，谁先疼？那个人/那道门在不在我们的循环里？** 在，它才真的存在；不在（P0、指针穿透、"光被纸盖住"都属于这种），就必须配一道人测或截图门，否则它不是约束，是运气。
4. **画面好不好看，目前没人看过。** 全仓唯一被浏览器真实跑出来的画面是 `docs/evidence/voxel-proof.png`。`field-ground` 的预览只保证"构建通过、无外部请求、装配断言绿"。**本文所有关于"好看"的描述都是设计意图，不是观察结果。** 要评价先截图。
5. **`costMs` 全部是估算。** 本文没有引用任何帧率数字，因为没有一个是真的在真机上采的。
