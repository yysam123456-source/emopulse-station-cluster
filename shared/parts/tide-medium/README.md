# tide-medium

**L0 底材**：`tide`（潮）biome 的屏幕空间介质 —— 色阶 / 光斑 / 雾 / 微粒。

## 定位：L0 不该试图模拟 L1 做的事

有 WebGPU 时 `voxel-world`（L1）会把 L0 **整块遮住（0 像素）**。所以：

> **L0 只在「没有 WebGPU」的那一档才被看见，而那一档里没有海床**（海床是 L1 的活）。

推论（这条挡掉的是一次看似合理的改进）：
- ❌ **不做 Worley 焦散网** —— 那等于"在有海的档看不见、在没海的档画一个没有海床可接的光网"。这不是更真，是**在错误的档里模拟一个不存在的对象**。
- ❌ **不做"只在下缘铺焦散"** —— L0 是满幅屏幕空间介质，它**没有"下缘是海床"这个概念**。一旦给了上下之分，它就变成半个场景零件，而场景零件的规矩（LOD、遮挡、与 L1 的关系）它一条都不遵守。
- ✅ **做圆斑/光丝的"水下散景"** —— 那是屏幕空间光氛围的正确形态。

字段名因此从 `caustic` 改成 **`glow`**：旧名承诺了实现做不到的事，**下一个人会按名字去改**。
改名成本是几处引用；不改的成本是下一个人花一天做 Worley，然后发现它在有 GPU 的机器上 0 像素。

## 参数

| 字段 | 状态 | 说明 |
|---|---|---|
| `grade` | 待裁 | 色阶（深蓝压暗 / 青绿提亮 / 近灰去饱和） |
| `glow` | 待裁 | `'spots'` 圆斑 / `'streaks'` 拉长光丝 / `'none'` 关 |
| `fog` | **已定** | 雾（上浓下淡 / 均匀 / 四周浓） |
| `motes` | **已定** | 微粒 64 个，随 LOD 减量 |

三组开关**各自独立可关**：`grade:false` / `glow:'none'` / `fog:false` / `motes:false`。关掉后仍不白屏（`bench` 断言）。

## 光斑的三条判据（产品给，`bench` 锁着）

```
数量        40–80（实测 56）
直径上限    ≤8% 画幅宽（实测 8.00%，1280 → 102.4px）
软边        ≤直径 25%（精灵 0.75R→1R 归零 = 占直径 12.5%）
```
**这三条是从"现在像云"这个失败样本反推的**（改前是 18 个直径 120–260px、软边≈100% 的大软盘）。

## 两条实现纪律

1. **静态形态 + 动态位置 → 烘精灵 + 盖印**。每帧 56 次 `drawImage`，而不是每帧 56 个 `createRadialGradient`（后者在真机上 5–8ms）。
2. **`screen` 混合的 alpha 不是"不透明度"，是"加多少光"**。第一版精灵峰值 `alpha=1.0` → 直接爆成白球/雪球。峰值 0.5 + 逐颗亮度（0.35–1.0）才读成光斑。

## 成本

`costMs = 1.8`（**估算**，未实测）：1 次不透明整屏 blit（1.3）+ 56 次精灵盖印 + 64 个微粒 arc + 两次 fill 的固定开销。
真机数值等 `bench-parts-browser` 补这一站。
