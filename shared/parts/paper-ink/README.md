# paper-ink

`room` / `ink` biome 的 **L0 底材**：程序化纸纹 + 暗角。只做一件事——铺一张看起来像纸的底。

- **来源**：自写（不来自 portal）。`docs/BIOME-ASSET-MAP.md` 的结论是「room 只需要 `paper-ink` + `pixel-post` 两件」，这是其中承重的那一件。
- **为什么不用 ink 引擎那份纸纹**：原件是 **273 KB base64 内联 PNG**（gzip 后仍约 205 KB）。L0 底材的预算是几 KB；而且它的 SVG 管线（`feTurbulence` + `feDisplacementMap`）不值得 port —— 同样的观感用 128×128 周期值噪声在 `createImageData` 里算一遍就有，还能种子化。**那条 base64 我一个字都没读。**
- **无缝是构造出来的**：值噪声的格点索引 `(x0+1) % gx` 回绕，于是 `u=0` 与 `u=1` 落到同一格、平铺边界天然连续。没有任何「镜像 / 羽化接缝」后处理。
  `bench.mjs` 会**用截下来的真实像素**验证这一点（按列/行均值比较跨缝跳变与内部 p90 跳变），并跑一条**阴性对照**（把末行末列压暗 30%）证明判据会红。实测：真实瓦片 0.75×（判据 <3 PASS），人造接缝 100×（判据正确报红）。
  顺带记一笔：把 `x0/y0` 的 `% gx` 去掉**不会**破坏无缝（`ix` 本来就取不到 `gx`），真正的无缝来源是 `x1 = (x0+1) % gx`；去掉它 → 比值 8.80×，判据当场红。
- **构图：它画的是一张纸，不是一层底纹**（2026-11-18 按产品判据改）。四周留出暖中暗台面（纸约占屏面 73%），纸带向下偏移的两层投影，读起来才"可以按下去、会留印"。铺满整屏的纹理 = 背景，不是纸。
- **暗角不在这里**：产品判定「纸上边缘发暗会读成旧照片滤镜」，暗角归 L4 `pixel-post` 的 `vignette`。本件的 `vignetteAlpha` 恒为 0，别再加回来。
- **✅ 已收口（2026-11-18）：`ink` biome 的纸铺满画布**（无边界、无台面、无方向光），符合产品口径"纸是载体"。
  代码已按 biome 分流：`sheetRect()` 对 `ink` 返回 `null`，绘制分支走整屏纸（`shared/parts/paper-ink/index.ts:47-48`、`:353-357`）。`room` / `field` 的纸仍是内缩 sheet + 台面。
- **双线框**：吸收 `sites/license/parts/index.ts` 的 `createPaperPart`（`strokeRect` 内缩 8.5px + 内层 3px），按 biome 分流（room/field 有边，ink 无边）。
- **低频结构故意很弱**：斑块 0.035 / 中频 0.028 / 纤维 0.05 / 颗粒 0.055。前两版斑块给到 0.10/0.05，在 128px 周期上会**看出一眼方格阵**（产品判据 6 的翻车点）。
- **成本**：`costMs = 1.3`，**估算**：1280×720@dpr2 = 3.69 Mpx 下 1 次不透明整屏 blit × 0.35 ms/Mpx。纸纹 / 晨光 / 暗角全烘在离屏里，`draw` 里连一次 `createGradient` 都没有。**浏览器实测未做**（Node 无 canvas，假 ctx 测出来 0.0004 ms，那只测 JS 指令发射）。
- **LOD**：`setLod('low')` 把瓦片 128→64 CSS px（设备像素 256→128）。**说实话：这只省烘焙成本与显存，每帧成本不变** —— 本件每帧只有 1 次 blit，已经没有可减的填充量。预算紧张时不该指望本件降档，应该去挂起 `expendable` 的 L2/L4。
- **已知限制**：离屏烘焙依赖 `document.createElement('canvas')`，缺失时降级为「纯色 + 缓存的 radial 渐变 + 420 个纸屑点」每帧矢量绘制（渐变对象跨帧复用，不重建）。
- **`reducedMotion`**：本件没有可减的运动（纸是静的），因此不受影响。
