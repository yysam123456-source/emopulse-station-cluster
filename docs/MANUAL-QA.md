# MANUAL-QA — 四站手测协议

> 自动化现已覆盖 6+ 门：`paper-visual` 10 · `field-visual` 6 · `tide-visual` 2 · `site-fingerprint` 7 · `site-dom` 70 · `preview-build` 738 · `input` 23 · `clock` 5 · `site-build` 102。**本文仍负责它们测不到的"这站能不能给人看"**——判据要可执行、可复现、可对照截图，不靠形容词。
>
> **总时长：四站 ≤ 40 分钟**（实测预算：前置 2 分钟 + 每站 3 分钟 + 记录 6 分钟 ≈ 20 分钟，留一倍余量）。
>
> **判据只有两种形态**：`是/否`，或一个**可量阈值**。**任何"看起来/感觉/差不多"都不合格**，包括"看起来不错"。

---

## 0. 怎么用

1. 按 §1 做前置（一次 2 分钟，四站共用）。
2. 逐站跑 §3–§6。每站一张清单，**勾是/否**，不写评语。
3. 按 §2 判：**阻断项（B）任一否 → 整站不过**，不必跑完；记录项（R）否 → 记下来但不拦。
4. 不过的站按 §7 记一行（哪一条、实测值、复现步骤），交给工程。
5. 每次改动后**只重跑受影响的站**，不要重跑全部。

**证据留存**：每站存三张图 —— `首屏.png`、`40s后.png`、`产物.png`。**没有这三张图的通过不作数。**

**无效证据要当场拒收，不要拿着它纠结**：`frames < 60`、宽度 < 1280、或处于 `degraded` 而降档的图，**一律不能作判定依据**——它们只能当"探针"用来分离原因（例如"形态不对"还是"降档放大"）。
> **一张不能用来判的图，比没有图更危险**——它会被当成证据。截图工具应在前置检查里直接拒出图并说明原因。

## 6. `/koi-pond` · ink（3 分钟）

判据来源：`PRODUCT-FORM` §1.4。

## 8. 附录：三个量的算法（可复制执行）

```python
# 统一口径：sRGB → 线性 → Y → L*（CIE 明度，0–100）
# lin(c) = c/12.92 if c<=0.04045 else ((c+0.055)/1.055)**2.4
# L*     = 116*Y**(1/3)-16 if Y>0.008856 else 903.3*Y
```

| 量 | 算法 | 用在哪 |
|---|---|---|
| **L\* 中位数** | 目标区域逐像素算 L\*，取 P50 | G7 / L5 / L6 / S5 |
| **方向光** | 对纸面区域做最小二乘平面拟合 `L = a·x + b·y + c`；报 `a、b`、`R²`，以及左上 20%×20% 块与右下块的均值差 | L3 |
| **周期条纹** | 目标区域**列均值**去趋势后：**tile 周期自相关（lag = 128×DPR）≤0.35**，且**中央区功率谱 max/median ≤400**。**不要用 lag 4–32 的绝对自相关**（平滑纹理恒高，门永远不过） | L7 |
| **两档一致性** | 同尺寸两张图逐像素 L\* 差的中位数与 P95 | S3 / K10 |
| **亮区** | **`L\* > P50 + 4`**（绝对偏移，相对中位）。**只在一个带内用**（例如"最上 30% 高度内"），不要全帧用——全帧用会被垂直梯度吃掉 | S11/S14 |
| **饱和度** | **固定用 HSV S = (max−min)/max**。换成 HSL S 会差 50%（实测同一张 `/hug`：HSV 0.472 / HSL 0.315）——**两个人都"量了饱和度"却对不上，只可能是公式不同** | 全部色指纹 |
| **量的来源决定断言的形状（三类，别压缩成两类）** | ① **纯函数算出来的 → `===`**（`costMs = 3.69×0.5`）；② **实测值 → 不许 `===`**，必须随数字记 **平台/分辨率/dpr/后端**，区间只能由"同一平台重复采样的离散度"决定；③ **估算值 → 既不许 `===` 也不许当门槛**，只能对账（打印出来，与估算过程并列）。分界一句：**等号只用于"我们能算出它"，不用于"我们测过它"。** | 全部性能项 |
| **别把单件判据抽象成通则** | `G11`（`costMs ===`）**只适用于 `pixel-post`**。同一字段在别的零件里来源不同：`voxel-world` 是**实测**（headless Edge + SwiftShader 0.05ms，换后端就变）、`field-ground`/`paper-ink` 是**按填充率估的**。若把 `G11` 抽成"所有零件 `costMs` 都要精确"，第一个红的就是 `voxel-world`，**而那个红是假的**——假红的下场和假绿一样：门被关掉。 | `G11` |
| **纯函数用等号，带噪声才用区间** | 由公式算出来的量（`costMs` 的纯函数分支、调用计数）**断言用 `===`**；带测量噪声的量（像素差、图差）才用区间/阈值。**混用会让"区间"变成逃生门**——有人会为了让它绿把常数往窗口里挪。分类：`G10`、`G11`（后者仅 `pixel-post`）属等号；`G9`、`S3b` 属区间 | G9 / G10 / G11 / S3b |
| **耗时不作门** | 帧耗时是**间接量**，噪声大：5ms 差可能被 GC/合成器吃掉。要判"有没有走某条路径"，用**确定性的计数/账实对账**：调用次数 = 0、`costMs` ≈ 公式值。**耗时只是旁证。** | G10 / G11 |
| **实测要标口径** | 任何性能数字必须附 **平台 / 分辨率 / dpr**，并区分 `cpuMs`（只算 JS、不含 GPU 填充）与 `costMs`（声明值，`planBudget` 只看它）。**declared 与 actual 是两个数，别混。** | 全部性能项 |
| **第 0 问也用开/关答** | "用户还缺这一样吗"是主观的，问五个人三种答案。所以**答案不由讨论给出，由一次开/关对照给出**：装上、再关掉，差异能不能用一句话说出"用户少了什么"。说不出 → 它本来就不该存在，后面关于"放哪儿"的讨论全部消失。`dither` 用这一问 5 分钟判死 | 所有新效果立项时 |
| **阈值必须写在感知侧** | 判据若跑在感知空间（L\*/像素差/面积占比），**阈值必须由至少一次换算给出**，不许把输入侧的百分比直接搬过来。`vignette 8%→14%` 看着差 6 个百分点，在 L\* 里只有 **0.6–0.8**——**百分比是输入，L\* 是输出。** | G12 |
| **两种仪器：离散用开/关、连续用推极端** | **离散**效果（装/不装某零件、某开关）用开/关对照；**连续**效果（`grain 0.04`、`vignette 8%`、某个系数）用**推到极端**（0 与上限各一次）。**关掉只能证明"它存在"，推到极端才能证明"它的量级是它声称的那个"。** 用后者必须写明：推到哪个极端、"变了"的判据是什么 | G12 / S3b |
| **开/关对照** | 凡是"这层/这个效果到底有没有生效"，**不要推理，出两张图**：同一 `(seed, t)`，开 / 关，比像素。**默认配置下该层不可见时，两张图必须逐像素相同**；该层可见时，必须能指出差异区域。这条比任何"我看见了"都硬——`vignette` 从没实现、`dither` 从没执行，两次都是靠这条才发现的 | S3b / G9 |
| **每条判据要两个样本** | 一个"**必须红**"的反例 + 一个"**必须绿**"的正常图。只写判据不写反例 = 没验。这和 `stage-mutation` 那 6 条变异探针是同一件事，只是那边验代码、这边验判据本身。G9 的反例：把砖换回静态贴图 → G9 必须红 | 全部 |
| **判据的形状** | 判据要写成**对某张具体图的否定**，不要写成**对某种感觉的肯定**：「中心零实体」→「中心 20%×20% 内不存在面积 >0.5% 且边缘闭合的亮块」。**半像素可算（截图 + 30 行脚本），圆盘会被抓红，"感觉"不会被抓红。** 凡写成"没有某种感觉"的判据都要按这个形状过一遍 | 全部 |
| **局部 vs 全局** | 测"某个东西亮不亮"必须**局部化**（中心 vs 邻域）。带全局梯度的画面里，任何全帧分位统计都会把梯度算进去：`tide-final` 的 `P95−P50 = 10.75` 里几乎没有光斑的贡献，全是那条 16 L\* 的上下梯度 | S12 / S14 |
| **取样时刻** | **`frames ≥ 60`（≈1s @60fps）之后取，并在报告里写明帧号**。持续运动的站（`/still` 的波光、`/koi-pond` 的水纹）**写死 `frames = 60`**，不要写"画面稳定后"——那几个站永远不会稳定，写"稳定"等于没约定。允许 ±0.05 的取样漂移 | 全部色指纹 |

## 10. 这份协议自己怎么被验（它也会失效）

按"这条约束被违反时谁先疼"自查：

| 约束 | 违反时谁先疼 | 在不在循环里 |
|---|---|---|
| G6 / H7 / K7（菜单不吃世界） | 用户：点静音把仪式毁了 | **不在**（本地测试永远绿）→ 必须靠本协议每轮手测 |
| L3（方向光） | 用户：看到一张贴图 | **不在** → 截图 + R² 阈值 |
| K6（`Watch` 不长墨） | 用户：池面永久多一团墨 | **不在** → 必须手测，且这是**反向**测试（验"没发生"） |
| G1~G5 | 我们：构建期可断言 | 在 → 应尽量前移到自动化 |

**结论**：上表里"不在循环里"的四条，是这份协议存在的全部理由。**如果将来它们都有了自动化门，这份协议可以缩短，但不要删——反向量（"没发生"）永远需要人再看一眼。**

## 11. 口径先钉死，数字才是证据（**读这一节再读下面的表**）

> ### 总纲：任何阈值都必须**附带它的量的定义**。
> "亮区"不是亮区，"自相关"不是自相关，"饱和度"不是饱和度 —— **它们各自至少有三种定义，
> 而选哪一种会决定结论。**

四次真实踩坑（每次都是"两边都报得出数，却说不清差在哪"）：

| 量 | 至少这三种定义 | 选错会怎样 | 定稿 |
|---|---|---|---|
| **饱和度** | HSL `S=(max−min)/(1−\|2L−1\|)` / HSV `S=(max−min)/max` / 相对纸白的差值 | 同一张 `/hug` 差 **0.157**（0.315 vs 0.472） | **HSV S** |
| **自相关** | 原序列 / 去趋势后 / 去趋势且换栅格（设备像素 vs CSS 像素） | 不去趋势时把**方向光判成周期**（0.986）；在设备像素上算把**放大插值判成梳子** | 40px 高通 + CSS 栅格 |
| **bbox（找纸）** | 固定亮度阈值 / 相对背景阈值 / 行列覆盖率首次 >3% | 固定阈值把**暗侧角裁掉** → 面积与比例偏低，**把正确产物判红**（59.3% / 1.531） | `L > 背景P50 + 15` |
| **亮区** | `P85` / `P50+0.5(P99−P50)` / `P50+4 L\*` | P85 数学上**封在 ~50%**（永远到不了 60%）；P99 版被顶端光斑锚住（29–39%） | **`P50+4 L\*`** |

同理还有一条：**判据的算法里，应当出现它要排除的那个变量**（去趋势=把光平面写进算法；相对背景=把背景写进算法；运动分割=把"草是唯一会动的"写进算法）。

## 12. 每条规则的「不适用」条件（必须可指认）

`§11` 的规则都会长出"何时不适用"。**这一格最容易退化成形容词**（"效果本应极弱时"／"视情况"／"小尺度不适用"），那和"中心没有可指认的物体"是同一类东西。

**验收这一格的标准**：**另一个人拿着一张图或一条命令，就能判断"我落不落在不适用里"。** 做不到的，说明它其实是"我不想被这条规则约束"的备注——**该删，不该写**。

| 规则 | 不适用（可指认） |
|---|---|
| 亮区 = `P50+4` | 该站**全帧单一亮度**（纯色底、无渐变）→ 无带可分，此时报"该量无意义"而不是判红 |
| 饱和度用 HSV S | 画面**近无彩**（饱和中位 < 0.05，如 `/koi-pond` 的纸）→ 只报 L\*，色相/饱和不参与判定 |
| 取样 `frames ≥ 60` | 该站**无进场动画**且首帧即终态 → 取 `frames=1` 亦可，但报告必须写明"静态站，frames=1" |
| 开/关对照（**离散**效果：装/不装某个零件或某项） | **无例外**。L0 恰恰是最干净的一次开/关（关掉 = 画布无内容 = 差异最大的一端，不是"无法比较"的边界） |
| 推到极端（**连续**效果：`grain 0.04`、`vignette 8%`、某个系数） | 不适用「关掉」这种仪器——连续量关到 0 只是它的一端。改**推到两端**（0 与上限各一次），并**写明推到哪个极端、"变了"的判据是什么** |
| 第 0 问用开/关答 | 该功能**尚未实现**（没有可关的东西）→ 直接判"不该存在"，不必做对照 |
| `G9` 颗粒随时间变化 | `grain = 0` 的站 |
| `S3b` L0 A/B | `vignette = 0` 的站不适用反向要求（关掉必须有两图差异） |
| `G11` `costMs ===` | 只适用 `pixel-post`；`voxel-world`（实测）、`field-ground`/`paper-ink`（估算）**不适用** |
| `S12`/`S13` `glow` 分布 | 该站 `glow: 'none'`（若某站决定不要光） |
| 耗时不作门 | **无例外**——所有性能判定都不许用帧耗时当门 |
| 判据两样本（红反例 + 绿正常图） | **无例外**——没有反例的判据等于没验 |

### 12.1 假红档案：**阈值卡在正确实现的边上**

门槛不一定错在"太严"——它也可能**离正确实现太近**。正确做法是把实现推到稳定区，**不是放宽门**。

| 案例 | 现象 | 根因 | 正解 |
|---|---|---|---|
| K1b `14.9%` vs 门槛 `15%` | 正确实现被判红 | 哈希抽样在 28 行只剩 ~9 段时把 `-4` 压到 **14.9%**，正好卡线。**门没错、实现没错，是抽样方法把正确实现卡在边上** | 工程师改用 **δ∈{2,3,4} 轮转**（三值各 33%）——**给实现留稳定余量，不是放宽门** |
| `vignette 8%→14%` 只有 0.6 L\* | 我按"相邻档 ≥2 L\*"写的门会把正确实现判红 | 把输入侧百分比当输出侧阈值；换算后只有 0.6–0.8 L\* | 阈值写在感知侧（§13 公式），按站给端点门 + 量级比 |
| bbox 固定亮度阈值 | 正确纸（64.4% / 1.4144）被量成 59.3% / 1.531 | 绝对阈值把方向光的暗侧角裁掉 | 相对背景阈值 `L > P50+15` |

## 13. `vignette` 的换算（公式优先，表只是示例）

语义：`vignette` 是**角部压暗比例**，`Y_corner = Y_center × (1 − v)`（黑覆盖层 alpha 混合等价于乘法）。

**公式（唯一权威，10 行可重算）**：

```
L*(v) = 116 · ( ((L*_center + 16)/116)³ × (1 − v) )^(1/3) − 16
理论差(0→v) = L*_center − L*(v)
```

**`L*_center` 永远取实测，不取标称值**——`paper-ink` 与水体底材的实际亮度会和明度带不完全一致，而且它们还会改（`paper-ink` 刚返工过）。

**下表只是"以当前实测值为例"，不是权威值。过期就按公式重算，别改表。**

| 站 | 中心 L\*（示例） | v=0.08 | v=0.14 | Δ(0.08→0.14) | **Δ(0→0.14)** |
|---|---|---|---|---|---|
| `/still` | 12 | 11.23 | 10.63 | 0.61 | **1.37** |
| `/license` | 20 | 19.01 | 18.23 | 0.78 | **1.77** |

**方向反直觉，容易让人以为数字错了**：`/license` 在**更亮**的底上，压暗的 L\* 差**更大**（1.77 > 1.37）——因为 L\* 是 Y 的立方根，亮区同一比例变化折算成 L\* 更多。

**两条结论**：

1. **阈值必须按站给，不能给全局数**——理论值随中心亮度变。这与 `costMs` 那次是同一个坑（同一字段、不同性质）。
2. **产品级**：在 `≤14%` 红线内，合法区间（8–14%）在 `/still` 暗部只有 **0.6 L\* 的差——肉眼不可分**。所以 **`vignette` 不能承担跨站差异**；`/license` 与 `/still` 的区别由**色指纹**承担（L\* 74 vs 26、色相 35° vs 208°、饱和 0.098 vs 0.58）。

### 13.1 `G12` 三项各指一条不同的代码路径

这是它比"红/绿"多给一倍信息的地方，成本只是多写两行报告：

| 观测 | 结论 | 动作 |
|---|---|---|
| 单调性破 **且** 端点差 ≈ 0 | **不存在**（没执行到那条路径） | 回去查代码分支（是不是又走了快路径/被 LOD 跳过） |
| 单调对、端点够、**量级比 < 0.7** | **有偏差**（曲线形状或中心位置错） | 查渐变形状与椭圆参数 |
| 单调对、端点够、**量级比 > 1.3** | **有偏差（反向）**：压得太狠，可能越了红线 | 查上限夹取（≤0.14） |
