## 1. 产品定义

### 1.1 一句话产品定义

把 10 个现成 3D/交互"零件"低成本拼装成一个情绪疗愈站群：以 abyssal-garden 为稳固底座，先上 /still 清静站，再依次插拔 /license、/praise、/hug 与锦鲤搜索长尾站；自研只占 ≤15%（情绪文案、凭证导出、短 URL+埋点、零件粘合）。

### 1.2 产品目标（3 个正交目标）

| 编号 | 目标 | 可衡量标准 |
| --- | --- | --- |
| G1 · 工程底座 | 建立稳固的共享底座与可插拔应用规范，使新增站点、换零件、调参数都不推翻底座 | 新增一个站点不需重写底座；`quality.js`/`math.js`/`audio.js`/`main.js` 骨架与构建脚本保持一行不改；配置项与站点逻辑分离 |
| G2 · 交付效率 | 以最小自研成本交付首发站并逐步扩展全站群 | 复制代码占比 ≥85%；/still 1 天内上线；静态 3D 场景从从零 2–4 周压缩到 1 天 |
| G3 · 用户体验 | 提供无聊天、无任务、无消费引导的情绪疗愈体验，形成可分享、可搜索的流量沉淀 | 全站零消费引导；每站一个明确主交互；/still 保留静坐计时与埋点；锦鲤三风格形成 3 个可搜索落地页 |

**产品级硬约束（G1 的强化表述，必须落实）**

> 底层架构一定要搭建好，坚实的基础架构方便后续应用层面不断增加的新应用，以及迭代、调整、优化。
> 即：站群 = 稳固共享底座 + 可插拔应用。底座的稳定性、可扩展性、可迭代性优先于单个站点的短期交付速度；任何站点实现都不得破坏底座，也不得让后续站点为复用而返工。

### 1.3 用户故事（访问者 / 站群运营者 / 开发者三类视角）

| # | 视角 | 用户故事 |
| --- | --- | --- |
| US1 | 访问者 | 作为一名情绪需要喘息的访问者，我希望进入一个安静的 3D 空间，不被聊天、任务或消费信息打扰，以便获得片刻平静。 |
| US2 | 访问者 | 作为一名想传递心意的访问者，我希望通过发证、夸夸小票或放飞拥抱把一份情绪凭证发给对方，以便得到有温度的回应（Hug them back）。 |
| US3 | 站群运营者 | 作为一名站群运营者，我希望用统一底座快速上线新站点、替换文案与配色，以便低成本测试新主题并沉淀搜索型长尾流量。 |
| US4 | 开发者 | 作为一名开发者，我希望从零件总库直接复制现成模块并接到统一状态机上，以便不重复造轮子，把自研量控制在 15% 以内。 |
| US5 | 开发者 | 作为一名开发者，我希望各站独立持有构建产物、共享源码骨架与构建脚本，以便改动一个站点不影响其他站点，迭代时无需推翻底座。 |

## 4. UI 设计要点

| 要点 | 说明 |
| --- | --- |
| 情绪化首屏 | 打开即进入 3D 场景：水/雾/光/焦散 + Web Audio 音景营造强氛围；首屏文案即情绪钩子。主题色通过 shaders.js 顶部常量切换（WCOL/PCOL/SUNC/EXPO/RAYS），首屏文案在 template.html 更换。 |
| 反向设计（/still 为范本） | 明确"不做"：无聊天、无任务、无消费引导、无注册打扰；静坐计时为唯一轻量反馈，克制的信息层级。 |
| 零消费引导 | 全站不出现付费、购买、订阅、广告位；凭证（许可证/小票）定位为情绪纪念品，而非营销券或转化入口。 |
| 交互即内容 | 每站一个主交互：/still 静坐、/license 盖章、/praise 指针拨开与小票吐出、/hug 放飞与吹气。UI 极简，交互本身承载情绪表达。 |
| 跨设备一致体验 | 复用 quality.js 三档画质 + 动态分辨率，保证不同设备流畅；音景与动画需提供用户可感知的开关入口（避免打扰）。 |
| 凭证视觉一致性 | 许可证走公文纸纹，小票走热敏纸纹 + 锯齿边与纸层前后关系；Canvas 导出图风格需与所在站点一致。 |
