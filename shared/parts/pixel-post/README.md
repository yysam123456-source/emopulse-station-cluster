# pixel-post

**L4 后处理**（整场唯一）。工厂函数形态：`makePixelPost(opts)` → `PartV2`，`part = makePixelPost()` 是缺省实例。

## 为什么是工厂，而不是"一个默认很强的零件"

上一版把「20px 块网格 + 逐块量化」写成了默认值。那是 `pixel-dissolve.js` 的**转场配方**，不是逐帧调色。结果 `/license` 的纸纹、暗角、晨光全被 64×36 个色块吃掉，整站读起来像"显示器坏了" —— 而所有门的指令计数断言都是绿的（它们数调用次数，不数画面）。

结论写成规则：**一个需要四站都覆盖一遍的默认值，就是错误的默认值。** 忘记配参应该退化成"几乎看不见"，不是"每站都被像素化"。

## 参数（全部有硬上限，超了夹住）

| 参数 | 缺省 | 上限 | 说明 |
|---|---|---|---|
| `grain` | 0.04 | 0.05 | 颗粒。**动能**：8 张 tile 按 `floor(t*24) % 8` 轮换（reducedMotion 冻在第 0 相） |
| `scanline` | 0 | 0.08 | 扫描线；`/license` 必须为 0（会读成复古滤镜）。只在 high 档画 |
| `vignette` | 0.08 | **0.14** | 暗角（椭圆，中心到角部线性）。**只由 L4 画**，站内不许再画一层 |

**已删（2026-11-18，架构师裁决）**：
- `dither` —— 它抖的是 `alpha < 255`，而合成链终点是**不透明整帧** → **任何站都不可能触发**。
  还强迫走 GPU→CPU 读回（实测 5.1ms），把 `/koi-pond` 顶到 9.78ms → 整站降档。
  判据是：**夹住之后效果还在 → 夹；效果根本不存在 → 删。**
- `blockPx` —— 四站规格没有一站要"像素块化"，它是整条读回路径唯一的理由。
  将来谁要块化，那是一件**新零件**，不是一个睡着的选项。

## 两条实现路径（按参数自动选，站点不用管）

**只有一条路径**：烘一张整屏覆盖图（暗角 + 扫描线 + 颗粒）→ 每帧 **1 次带 alpha 的 blit**。
**不读回任何像素**（`getImageData` / `putImageData` 均为 0，bench 断言）。
读回路径已随 `dither`/`blockPx` 一起删除 —— 它曾是整套里唯一一处 GPU→CPU 读回，成本随驱动波动（同一份代码 3–10ms 都见过），**不可预测的成本会污染所有站的预算判断**。
- **全中性**（0/0/0 且无抖动无块）：`draw()` 直接返回，**连资源都不建**。装一个什么都不做的 L4 不该有成本。

## 成本

`costMs` **由参数算出**（不是常量）：关掉扫描线/抖动会少一整个全屏 pass，而 `planBudget` 的降档决策全靠它 —— costMs 不变等于在预算账上撒谎。
- 快路径 ≈ 1.85 ms（3.69 Mpx × 0.5 ms/Mpx 带 alpha blit）**估算**
- 全中性 = 0.01 ms（什么都没做）

`node bench.mjs` 打印六条断言：每帧 1 次 blit / **getImageData+putImageData = 0** / **颗粒换相（3 帧 tile 不同）** / 三对开/关数字 / 全中性零指令 / costMs 随参数变。

## 已知的两个坑（都踩过）

1. **`putImageData` 不能写主画布**：它不做混合、直接覆盖（含 alpha），会把 L0/L2 抹掉。正确顺序是「小缓冲 putImageData → 主画布 clearRect → drawImage 放大贴回」。
2. **量化前必须先夹到 255**：`262 & 0xf8 === 0`，位运算越界会把通道清零 → 浅色纸面上随机出现青色方块。这是真浏览器截图里发现的，当时指令计数断言全绿。

## 开/关一对数字（bench 强制）

架构师的要求：**每个零件的 bench 必须吐一对"开/关"可辨数字**，因为"它有没有在工作"不能靠眼睛
（产品经理就是在 1:1 下"看见网点"、其实是抗锯齿才误判的）。本件 bench 出三对：

```
vignette  关 → radial 0 次 / 开 → 1 次，终点色 rgba(0,0,0,0.14)
grain     关 → pattern 0 次 / 开 → 2 次
scanline  关 → pattern 0 次 / 开 → 1 次
```
