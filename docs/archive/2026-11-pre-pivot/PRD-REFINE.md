### 0.2 我不同意的三处

① **koi 三站不是"同一产品换 3 套着色器"，是同一产品换 3 个颜色数组。** `sites/koi/shared/koi.ts` 共 78 行，`createKoiPart` 里 9 条鱼由 `PALETTES[style]` + `ink: boolean` 驱动；文件头注释自陈"按原件三着色器的视觉参数**移植为 Canvas 2D 实现**"。原件 13 文件 166 KB 根本没进产物。三个 dist 体积 107,849 / 107,851 / 107,882 B，**彼此差 ≤ 33 B**——这已经不是"三套着色器"，是"三套配色常量"。这直接影响矩阵里 koi 的处理方式（见 §2.3）。

② **"6/7 站从没做完"应改为"6/7 站有两个互相抢位置的主按钮"。** 那 6 站的主交互按钮其实填对了文案（`Stamp it`/`Print one`/`Let it go`/`Watch`），问题是把继承自底座的 `#d Enter scene` 也留在了首屏，于是首屏出现**两个同权重的主按钮**，用户不知道该按哪个。这是比"占位符没换"更难发现、也更伤转化的缺陷——占位符是显性 bug，双主按钮是结构性 bug。`/hug` 更夸张：`.row` 里塞了 **6 枚按钮**（`Hug them back` / `Share` / `Use mic` / `Listen` / `Leave` / `Enter scene`）+ `#act`，共 7 枚。

③ **主理人漏了两条硬伤，我认为都该进 `补完硬伤` 这一步：**

- **竖屏手机被强制转 90°。** 7 站全部含 `@media (orientation:portrait) and (pointer:coarse){ body{ transform: rotate(90deg) translateY(-100%) } }`。手机竖着打开，页面横过来，用户必须转动手机才能看。这是首屏第一秒的可用性事故，优先级不低于 CTA。
- **工程开关占据首屏。** `#q`（Detail: Low/Medium/High 画质档）和 `#k`（键位表）在 7 站首屏都是可见元素——用户看到的是开发者的调试面板。

- **非 Chromium 用户首屏被挂广告。** `shared/core/src/main.js:22` 是 `$('w').hidden = !!navigator.userAgentData;`——`#w` 只在有 `userAgentData` 的浏览器上隐藏。所以 **Firefox 与 Safari 用户首屏永久看到一行 `Use Google Chrome for optimal experience`**，位置在加载进度条下方、主按钮上方。这两类浏览器的用户被要求换浏览器才开始用产品。

### 0.3 我新增的三条硬约束（实测得出，不是估计）

**A. 多 biome 必须构建期择一，否则体积门必破。**
用 esbuild 实测各源文件 minify 后体积：`world.js` **24,945 B (24.4 KiB)**、`main.js` 30,247 B、`shaders.js` 41,851 B、`math.js` 6,985 B、`audio.js` 2,924 B。当前 dist 体积 107,773–112,590 B，硬门 163,840 B，**最大余量**（hug.html）`163,840 − 111,961 = 51,879 B ≈ 50.7 KiB`。
若把 4 个 biome 全打进每个产物（运行时切换），world 部分约 `4 × 24.4 ≈ 98 KiB`，每站 185 KiB 以上，**4 个 biome 全超门**。
→ 结论：biome 只能**构建期择一**（esbuild define + dead code elimination，或按站点裁剪 `FILES` 拼接列表），产物内只含本 biome 的生成代码。这不是性能优化，是能不能继续用 160 KiB 当闸门的问题。**本 PRD 不放宽体积门。** 详见 §8.3。

**B. 零外部请求现在只是"没有配置"的巧合，不是设计保证。**
7 个 dist 里 `navigator.sendBeacon` 与 `fetch(` 的符号各出现 1 处（`shared/contract/analytics.ts` 的上报分支）。`analytics.ts` 头注释写明"未配置端点时只写本地队列"——只是端点为空，代码在。这意味着"无服务端"这条卖点**今天无法靠读产物验证**。
→ 本期要求从产物移除上报网络分支（保留 `track()` 本地队列 API），让"产物内 0 个网络符号"成为可自动断言的事实。

**C. 全站 0 外链已达成，这条要守住。** 7 个 dist `grep` 出 0 个 `http(s)://`——底座模板里的 GitHub / Ko-fi 两个外链（`shared/core/template.html:148-149`）已被站点 override 全部移除。这是现有代码里已经做对的一件事，别在扩站时加回来。

**D. canvas-only 站点今天会直接构建失败，必须给构建管線加一个 `renderer` 分支。**（主理人实测，本节唯一一条"不做就无法开始"的工程约束）

- `shared/build/build.mjs:127`：`const injected = injectTheme(joined, config.theme);` —— **无条件执行**。
- `shared/build/build.mjs:135` 调用 `assertArtifact`（定义在 `:78`），要求 5 个注入值必须出现在产物里。

而 §2.2 裁决 `room` 与 `ink` **不走体素 raymarcher、不内联 WGSL**。没有 WGSL 就没有 `WCOL/PCOL/SUNC/EXPO/RAYS` 五个锚点 → `injectTheme` 抛错，`assertArtifact` 也过不了。**所以这不是优化，是前置条件。**

要求：

> `site.manifest.ts` 新增 `renderer: 'raymarch' | 'canvas'`，**缺省 `'raymarch'`**。
> `build.mjs` 对 `'canvas'` 分支跳过 `resolveOverlay`（L0 拼接）+ `injectTheme` + `assertArtifact` 的 theme 部分。
> **7 个 legacy 站 `renderer` 缺省即旧行为，产物逐字节不变**——这条必须用 `tests/baseline-dist.sha256` 的 7/7 证明，不是声称。

附带利好（写进 §8.3）：canvas 站点不内联 32 KB WGSL + 24.9 KB `world.js` + 27.4 KB `main.js`，产物从 ~107 KB 掉到 ~20–40 KB 量级。**体积门从"要小心"变成"根本碰不到"。**

## 1. 产品定位重写

### 1.1 一句话定义

> **Emopulse 是 10 个房间，不是 1 个网站。每个房间只接收一种具体的情绪状态，用户在到达之前就已经在搜索或分享里选好了门；因为没有账号，所以"认识用户"这件事由"选哪扇门"来完成，而不是由系统记录来完成。**

这句话同时解释了"为什么必须是 10+ 个站"：

- **没有账号 = 没有状态识别。** 一个站点要同时服务"我累到不想回答任何问题"和"我觉得自己是别人的负担"，它就只能做成一个通用冥想 App——中间态、平均态、对谁都不够准确。零 PII 底线切断了"识别用户此刻是什么状态"的唯一可靠路径，于是**唯一剩下的路径是让用户自己选门**。10 个门不是 10 个产品，是无画像系统下的"状态路由表"。
- **情绪查询是互斥的长尾。** 「I feel like a burden」和「I miss someone」是两个不重叠的搜索意图，落地到同一页会让第二个词组的人立刻离开。一个站只能吃一个词组族。
- **一个房间只够放一件事。** 物理隐喻：把 10 个情绪塞进一个页面 = 酒店大堂，谁也不想在大堂里哭。分开 = 10 间单间，每间只干一件事。

### 1.2 三个正交目标

| 编号 | 目标 | 可衡量标准 |
|---|---|---|
| **G1 · 语义自洽** | 每个站的世界观 = 文案 = 主交互 = 带走物，四者一条链不能断 | 每站 `site.biome` 与主文案、主交互材质、2D 零件的 `part.biome` 声明**构建期**必须一致，不一致则 build 失败（§5.5）；人工验收项：首屏 3 秒内看不出"文案在说 A、画面在放 B" |
| **G2 · 可到达** | 12 条路由每条都有独立的搜索落点与分享理由，不是同域重复内容 | 每站 title ≤ 60 字符、description ≤ 155 字符、keywords ≤ 5 组，且**互不重复**；首屏可索引正文 ≥ 25 词；`?from=` 之外的跨站链接数 = 0 |
| **G3 · 可复访（零 PII 内）** | 每站至少一条不依赖账号、通知、连续签到的回访理由 | 每站至少满足 1 条：(a) 产物可再生成且每次不同；(b) 同一 URL 的世界随时间变化；(c) 分享对象可能回赠。三条都不满足的站不得进矩阵 |

## 2. 生态与产品矩阵

### 2.1 世界（biome）的定义原则

现有 `world.js` 的生成器结构是四段：**地形噪声 + 表面网（surface nets）+ 柱状植被 + 环绕生物/道具**，六张硬编码常量表（`MESAS`/`ARCHES`/`HOLES`/`CLEARS`/`KELPZ`/`NOKELP`/`MAGENTA`）定义了一个具体地点。

因此 biome 不该按"故事"定义（那样每站都要写一个新引擎），而该按**同一套生成器的四个可调轴**定义：

1. **介质**：水 / 空气 / 无（静物）—— 决定着色与后处理
2. **地形**：3D 噪声起伏 / 平面 —— 省略地形就省掉 `surface nets`，产物反而更小
3. **植被**：柱状体（海藻/芦苇/草簇）或 无
4. **生物/道具**：环绕飞行的生物、环境粒子、少数大体量道具

**4 个 biome 就够覆盖 12 站，不要做 8 个。** 每多一个 biome，就多一份要长期维护的地形参数与视觉调校，而 12 个站里有 5 个是"室内"，根本不需要地形。

### 2.2 四个世界

| biome | 中文 | **渲染路径** | 介质 | 地形 | 植被 | 生物/道具 | 材质语言 | 服务哪种情绪 |
|---|---|---|---|---|---|---|---|---|
| `tide` | 潮 | **体素 raymarcher（复用 L0）** | 水（深，有折射与焦散） | 3D 噪声地貌 | 柱状海藻/海绵珊瑚 | 蝠鲼、气泡、沉船 | 折射 + 模糊 + 体积光 | 被淹没、想沉下去、累到不想说话 |
| `field` | 野 | **体素 raymarcher（fork `world.js`）** | 空气（分层雾 + 漂浮颗粒） | 低起伏丘陵 | 草簇、蒲公英 | 飞鸟/蝴蝶、风 | 长焦 + 颗粒 + 单向风 | 想轻一点、想放下、喘不上气 |
| `room` | 室 | **Canvas2D + 分层纵深（不内联 WGSL）** | 无（静物，无透视纵深） | 平面 | 无 | 桌、纸、打印机、椅子、玻璃 | 硬边 + 纸纹 + 单光源 | 需要被承认、被记录、被原谅 |
| `ink` | 墨 | **Canvas2D 水墨（不内联 WGSL）** | 浅水（无折射，墨扩散） | 平缓 | 芦苇、莲叶 | 锦鲤 | 纸 + 单色晕染 | 什么都不想解决，只想看点什么 |

**`room` 与 `ink` 不走体素 raymarcher，这是本期最重要的成本裁决。**

理由来自架构师的独立评估：现有引擎是 **384 m 尺度的体素 raymarcher**——世界包围盒在 `math.js:54`、`shaders.js:258`、`shaders.js:715`、`world.js:362` **四处重复**，碰撞砖 `CO=52 / CN=102` 在 `main.js`。一个 8 m 的房间在这个网格里只有约 11 个体素。架构师原话：**"不要用现有体素框架做室内"**——要做得连带改 4 处包围盒 + 碰撞砖，成本远超收益。

而 `room` 本来就不需要它：`sites/license/parts/index.ts`（paper / timeline / stamp / plane）与 `sites/praise/parts/index.ts`（receipt-paper / layers / pointer / typewriter）**今天就已经全部是 Canvas2D 绘制**——桌子、纸、印章、打印头都是 2D 画的，3D 只是背景。把产品面从"浮在 3D 上的信箱横条"扩成**全屏 2D 构图**，是减法不是加法。

由此得到本期真实的工程量分布：

| biome | 需要 fork `world.js`？ | 需要内联 WGSL？ | 工期量级 |
|---|---|---|---|
| `tide` | 否（仅参数与布景增删） | 是（复用 L0） | 低 |
| `field` | **是，且是唯一一个** | 是 | 4–6 天 |
| `room` | 否 | **否** | 低 |
| `ink` | 否 | **否** | 低 |

**4 个 biome 里只有 `field` 一个需要动 3D 引擎。** 这是刻意的排布：把最贵的工程量压在唯一一个必须压的地方，其余三个走 2D 路线。

**`room` 因此成为成本最低的 biome**，并承载 5 个站的骨架。这是刻意的：把"需要被记录"这一族（搜索量最大的一族）放在最便宜的渲染路径上。但**便宜不等于可以偷懒**——5 站共用一个世界最可能的退化方式是"5 站变成同一台打印机的 5 种纸"，诊断信号与硬验收见 §2.5-⑤。

### 2.3 koi 三站的处理（必须先定，否则矩阵算不清）

**现状（实测）**：3 个站是 78 行 Canvas 2D 代码 + 3 个调色板对象，产物体积差 ≤ 33 B。它们不是三个产品。

**决定：合并为 1 个产品、3 条路由。**

- 产品层：1 个站 `koi`，带风格切换（pond / ink / watercolor），切换器**只在 Esc 菜单里的二级位置**，不进首屏。
- 路由层：保留 `/koi-pond`、`/koi-ink`、`/koi-watercolor` 三条，构建期锁定各自的风格、title、description、keywords、H1、正文段落。

**论证（为什么不是砍成 1 条路由，也不是保持 3 个产品）：**

1. **SEO**：三个词组的意图确实不同（`koi pond` = 看/养鱼，`ink koi` = 水墨画，`watercolor koi` = 水彩画），但也正因此，三份**几乎相同的正文**是同域重复内容的教科书案例。合并成"一套骨架 + 三套差异化首屏/标题/正文首段"后，重复度下降而非上升，同时 3 个词组都有独立落点。
2. **成本**：3 套独立维护的样式表 = 0 收益。合并后调一次鱼群行为，3 条路由同时受益。
3. **为什么不砍到 1 条**：`ink koi` 与 `watercolor koi` 是"美术/绘画"意图，`koi pond` 是"场景/氛围"意图。用 pond 的落地页接 ink 的搜索词，跳出率会极高。三条路由是三个门，符合 §1.1。
4. **风险**：合并后 3 条路由容易退化成"仅 meta 不同"的软重复。硬护栏：三条路由的 H1、第一个正文段落、首屏 2D 构图（鱼的密度/水纹方向/有无莲叶）必须不同，构建期断言这三项两两不等。

### 2.5 压力测试：我自己想砍和想合的 5 处

**① 砍 `/drift`（曾计划的 field 第 3 站：松手，让视线随风漂）。**
理由：它的"情绪意图"无法与 `/still` 用一句话区分开——两者都是"什么都不用做"。区别只在介质（风 vs 水），而介质是**视觉**差异，不是**情绪**差异。更致命的是带走物：一个人漂完之后手里没有任何东西，"漂完了"不是产物。**三条 G3 回访理由它一条不满足。** 砍。

**② 砍 `/sleep`（曾计划：关灯，看天花板上的光斑消失）。**
理由：目标用户是"要睡着的人"，而睡着的人**不会带走图片**——带走物在这个场景里物理上不存在。同时"帮助入睡"是不可验证的健康声明，会逼着我们写无法证明的话（违反 §7）。砍。要处理"睡不着"这个词组，正确做法是把它并进 `/breath` 的 description，而不是新开一个站。

**③ 保留 `/breath`，但它是全站最危险的一站。**
它是 12 站里最像"通用冥想 App"的一个，也最容易滑向"连续天数 / 今日打卡 / 你来过 3 天了"。保留的理由：呼吸是唯一**不依赖视觉资产**就能产生停留的机制（纯节奏），而且 `?pace=` 是全站最强的传播单元（一个链接就能把"我的节奏"给别人）。附带硬护栏：`/breath` 不得出现天数、不得出现"今日已完成"、不得出现连续标记（见 §4.4 陷阱 B）。

**④ 合并 koi 三站为一个产品 + 三条路由**（论证见 §2.3）。

**⑤ 我承认 `room` 承载 5 站是过载，并给出诊断信号。**
5 个房间共用一个"室内静物"世界，最容易的退化方式是**5 站变成同一台打印机的 5 种纸**——`/license`、`/praise`、`/burden`、`/unseen`、`/miss` 的带走物全是"一张纸的 PNG"。如果发生这件事，`room` 就不是一个世界，是一个模板。
诊断信号（可人工验收，写进 §7 手测协议）：**如果 5 个 room 站的带走物里有 ≥ 3 个的 PNG 共享同一套纸纹 + 同一个印章位置 + 同一种排版骨架，判为退化。** 缓解手段：`/unseen` 的产物改为"座位号卡片"（无纸纹，深色卡片，只有一枚数字）、`/miss` 的产物为"玻璃上一帧"，只允许其中 3 站使用纸纹。`room` 的纸不是通行证，只有"被正式记录"的那 3 站才配得上纸。

## 3. 每站核心循环

**三段的定义（全站统一）**

- **进入**：头 3 秒。用户看到什么、听到什么、感到什么。只允许 3 层可见元素：H1（≤ 2 词）、一行 hook（≤ 12 词）、一个主按钮（≤ 3 词）。其余全部收进 Esc 菜单（§4.5）。
- **沉浸**：能停留的过程。"什么都不做"也算有效沉浸，但**必须有方向性的变化**——不是循环动画，是慢变量（光在变暗、水在退、纸在变黄、雾在变厚）。周期 ≥ 40s，振幅 ≤ 画布 4%。目标停留 60–240s 为佳，不设上限。
- **带走**：能脱离本站存在的产物。只允许 4 种形态：**PNG / URL / 纯文本 / 本地记录**。每站至少 1 种，且 12 站中 ≥ 10 站必须有 2 种以上（理由：只给图片的站，在"想立刻发一句话给人"这个最高频的传播场景里是空的）。

---

### 3.1 `/still` · tide · 改造

- **进入**：全屏水面，H1 `Still`，hook `Nothing here needs an answer.`，一个按钮 `Sit`。不加载任何 2D 面板。
- **沉浸**：按下 `Sit` 后镜头下潜到水位线以下约 1.2 单位，上方出现折射光带；声音（若开）从空气感变为闷水感。**慢变量**：光带亮度和角度在 4 分钟内单调递减，像日落从水面退走；偶发一串气泡从下方升起。不点任何东西也能停留——因为画面在缓慢变暗。
- **带走**：`Take it with you` 在停留 ≥ 60s 后出现（不是一开始就给）。产出 720×1000 PNG：静坐时长（等宽字体，如 `14 MIN`）+ 一句环境描述（`The light left at 21:40.`）+ 无排名、无对比、无"你超过了 X% 的人"。
- **停留机制**：光衰减。这是全站最便宜也最有效的停留机制——用户会不自觉等"光再暗一点"。

### 3.2 `/sink` · tide · 新增

- **进入**：水面仰视视角，H1 `Sink`，hook `Down where nobody can ask.`，按钮 `Hold to sink`。
- **沉浸**：按住不动即下沉，每 10 单位深度光照衰减一档（`EXPO` 与雾密度联动），到最深处只剩粒子与自己的呼吸声；一路上有 3 个可选择的"经过物"（一块沉石、一段断桅、一束上浮的气泡），碰到会轻微停顿但不产生任务。松手缓慢上浮，上浮比下沉慢 2 倍——**上浮的阻力就是这一站的语义**。
- **带走**：`?d=<整数>` 深度链接（可重放同一深度）+ PNG 深度卡（`−62` + 一句）。
- **停留机制**：下沉/上浮的不对称 + 深度带来的视觉变化是连续的，没有终点线，用户自己决定停在哪。
- **红线**：**不做"最深记录"、不做排行、不做"你是今天第 X 个沉到这里的人"**（那就是打卡，见 §4.4）。

### 3.3 `/hug` · field · 改造

- **进入**：黄昏草原，一株蒲公英占画面中央偏下，H1 `Hug`，hook `Send one. They can send one back.`，按钮 `Let it go`。**首屏只留这一个按钮**，`Share` / `Use mic` / `Hug them back` 全部移到 Esc 菜单或事件后出现。
- **沉浸**：蒲公英按状态机 `ready → drifting → away` 错峰释放绒毛（保留现有 `DandelionMeadow` 三状态机与 `aRelease`/`DETACH_SECONDS`）。**慢变量**：太阳高度角下降，草的受光从金色变紫，风的方向在 90s 内缓慢旋转。用户可以在"还没放飞"的状态里一直待着——绒毛会随风轻轻晃。
- **带走**：`?from=<token>` 链接（纯前端 base64url，`shared/contract/short-url.ts` 已有）+ PNG 已寄出卡。**回赠必须是一次点击可完成的**（现在要先复制链接再等人，闭环太长）。
- **停留机制**：风与光。用户会等"风来的那一阵"再松手——这是把停留变成仪式，而不是把停留变成等待。

### 3.4 `/breath` · field · 新增

- **进入**：雾气弥漫的草原，画布中央一个直径约 30% 屏高的圆环，H1 `Breath`，hook `Four counts in. Seven out.`，按钮 `Follow it`。
- **沉浸**：圆环按 4-7-8 缩放，雾气随每一次呼气向外推散一小段，吸气时缓慢回聚。**慢变量**：连续 8 次呼吸后，雾的整体浓度下降一档（画面变清），16 次后再降一档。用户随时可以走，走的时候没有"未完成"。
- **带走**：`?pace=4-7-8` 或 `?pace=4-4-4-4` 链接（把自己的节奏给别人）+ PNG 呼吸卡（`12 BREATHS` + 一句）。
- **停留机制**：**唯一的强制节奏器**。这是全站唯一"用户不需要决定做什么"的站——跟着走就行。
- **红线**：无天数、无连续标记、无"今日已完成"、无提醒（§4.4 陷阱 B）。

### 3.5 `/license` · room · 改造

- **进入**：一张桌子的俯视角，H1 `License`，hook `A permit to simply be.`，按钮 `Stamp it`。**首屏只有这一枚按钮**（现在有 `Stamp it` / `Save license` / `Listen` / `Leave` / `Enter scene` 五枚 + 画质三档 + 键位表）。
- **沉浸**：三段时间轴 `verifying → stamping → approved`，每段 2.5–4s，共约 9s。**这不是停留，是一次性仪式——所以"沉浸"用另一个机制补：审批结束后桌面不清空**，印章会留在纸上，用户可以继续在桌面上做无意义的事（把纸角折起来、把印泥盖歪一点再盖一次、把台灯挪一下）。这些动作**不产生结果**，只是让桌子是"活的"。
  - 诚实说明：`/license` 本质上是一次性仪式，它的"沉浸"最短。这是可接受的（G3 靠 (a) 产物可再生成且每次不同——编号不同、宣言句不同）。
- **带走**：720×1000 PNG（720 宽在 2x 屏导出 1440×2000，单张 ≤ 300 KB）+ **纯文本**宣言句（点 `Copy the words` 得到一段可直接粘贴进对话框的文字——这是许可证最常见的用法：发给一个不肯休息的人）。**全站唯一允许带纸纹 + 朱砂印章的位置之一**（§5.3）。
- **停留机制**：桌面的可摆弄性 + 审批时间轴的节奏感。不追求长停留，追求"这三秒是庄重的"。

### 3.6 `/praise` · room · 改造

- **进入**：柜台俯视角 + 一台热敏打印机，H1 `Praise`，hook `A receipt of good things.`，按钮 `Print one`。
- **沉浸**：小票逐行吐出（本地模板引擎 `makeTicket`，保留确定性种子）。**慢变量**：热敏纸在 3 分钟内缓慢变淡（这是热敏纸的真实物理特性），用户能看见"它会消失"。鼠标靠近纸层可以把纸拨开一点（保留现有 `paper-plane` 纸层遮挡思路）。
- **带走**：小票 PNG 720×1000 + **纯文本**三句夸赞（`Copy the words`）。**允许纸纹但不允许朱砂印章**——小票不是公文，它该有一个"已核对"的浅色打勾，不是印章。这是我改掉现有实现的一点：现在小票上写 `A+` 当印章，视觉上和许可证撞了。
- **停留机制**：纸在变淡。用户会盯着它看，因为"它在消失"比"它是静态的"更让人停住。

### 3.7 `/burden` · room · 新增

- **进入**：一个空柜台，柜台后没有人。H1 `Burden`，hook `Leave it here. You can come back for it.`，按钮 `Put it down`。**没有任何表单**。
- **沉浸**：拖/搬一件无名的重物（一个纸箱，重量用积木式位移表现）到柜台上，然后取一张寄存单。**慢变量**：房间的光从冷白变成暖黄（像店里要打烊了），货架上其他箱子逐渐变多——**别的箱子不是别人寄存的**（那是编造社交证据），只是这个房间本来就有很多箱子。用户可以在柜台前站很久，箱子不会催他。
- **带走**：寄存单 PNG（编号 `B-0417` + 日期 + 一行 `NO ONE WILL READ THIS.`）+ 纯文本编号。
- **停留机制**：搬箱子的物理反抗感 + 环境变暖。这是一站"有一次动作、可以慢慢做"的房间。
- **红线**：**不做"寄存了多少件"的总数展示**（会变成排行榜）、不做"取回"功能（取回就是任务，见 §4.4 陷阱 C）。

### 3.8 `/unseen` · room · 新增

- **进入**：暗场，只有一排排椅子的轮廓，H1 `Unseen`，hook `Someone kept a seat.`，按钮 `Sit down`。
- **沉浸**：坐下后，暗场里 200 张椅子中**一张**缓慢亮起（暖光），镜头用 8 秒缓慢推向它。亮起的那张是随机的（种子来自本地时间，不可复现——这一次就是这一次）。之后画面停留，那张椅子一直亮着。**慢变量**：其他椅子的轮廓逐渐被雾吞掉，只剩那一张。
- **带走**：座位号卡片 PNG（**深色卡片，无纸纹，只有一枚等宽数字**，如 `SEAT 137`）+ **纯文本**座位号。
- **停留机制**：推近的 8 秒本身就是停留；之后那张亮着的椅子会让人不想马上关掉。
- **红线**：**不说"有人为你留了座位"这类编造社交证据的话。** 文案必须是 `Someone kept a seat.`（陈述房间状态），不能是 `A stranger saved this for you.`（编造一个不存在的人）。这是本 PRD 唯一一条涉及"诚实"的文案硬规则，见 §6.4。

### 3.9 `/miss` · room · 新增

- **进入**：一块起雾的玻璃（室内窗），H1 `Miss`，hook `Write it. It fades, not vanishes.`，按钮 `Write`。
- **沉浸**：手指/鼠标在玻璃上写字。**字迹是本地 Canvas 渲染，不上传、不存储、不发送**。写完后字迹在 90 秒内逐渐变淡但不完全消失（保留 8% 不透明度），像真的在玻璃上一样。**慢变量**：窗外的光从傍晚过渡到夜色，玻璃内侧的雾气在下方慢慢凝结成水痕。
- **带走**：`Keep this` 生成 PNG——**"字迹将散未散的一帧"**，含用户自己写的字（本地渲染，绝不离开浏览器）+ 时间。
- **停留机制**：写字本身需要时间（这是全站唯一需要用户"动手较久"的站），写完之后会等它淡。
- **红线（最严）**：这是全站唯一有自由输入的站。硬约束：① 输入内容只进 Canvas，**不进 DOM、不进 localStorage、不进任何网络请求**；② 页面关闭即销毁；③ 不做"分享你的字迹"（那等于让用户把自己的话发到网上）。

### 3.10–3.12 `/koi-pond` `/koi-ink` `/koi-watercolor` · ink · 改造（合并）

- **进入**：水面俯视，H1 分别为 `Koi Pond` / `Ink Koi` / `Watercolor Koi`，三条路由的 hook 与第一个正文段落**必须不同**（§2.3 论证 4）。按钮统一 `Watch`。首屏**不放风格切换器**。
- **沉浸**：鱼群 + 水纹 + 慢速的光斑。**慢变量**：水纹相位 60s 一周期，鱼群在 5 分钟内会整体换一次方向（像真的池塘）。**允许"什么都不做"停留**——这是全站唯一一个"看就够了"的站，也是它存在的全部理由。三条路由的构图差异：pond 有莲叶、鱼 9 条；ink 无莲叶、鱼 5 条、有墨晕；watercolor 鱼 13 条、水纹最慢。
- **带走**：`?s=<seed>` 种子链接（同一 seed 在任何人的机器上重现同一片水面）+ 当日水面 PNG。**这是 koi 从"看鱼"变成"产品"的唯一杠杆**——它让"看鱼"产出一个可以被指认的东西：*look at my pond today*。
- **停留机制**：鱼群换向 + 水纹。目标是全站最长停留站（目标中位 120s+）。
- **红线**：不做喂食、不做收集鱼种、不做"你解锁了新的鱼"（见 §4.4 陷阱 A）。

## 4. 反向设计红线

### 4.1 沿用并强化的五条

| 红线 | 强化后的表述 |
|---|---|
| 无聊天 | 无评论区、无留言墙、无"匿名说一句"（匿名留言 = 零 PII 的破口，因为 UGC 需要审核，审核需要人工，人工需要看内容）。**`/miss` 的写字不在此例外**：字不进 DOM、不上传、不展示给任何人。 |
| 无任务 | 无进度条、无"完成 3 步"、无清单、无解锁。**唯一允许的序列是"动作 → 结果"（1 步）**，超过 1 步就要重新论证。 |
| 无消费引导 | 无付费、无订阅、无广告位、无赞助、无捐赠链接（底座模板里的 Ko-fi 已移除，必须守住——实测 7 个 dist 外链数为 0）。凭证是纪念品，不是优惠券。 |
| 零 PII | 不收集邮箱/手机/姓名/地区/IP 之外的任何标识。**"IP"这条要诚实**：静态托管的访问日志天然含 IP，这不是我们收集的，但也不能说"我们完全不知道任何人来过"。准确表述：**产品不请求、不存储、不传输任何用户提供的身份信息。** |
| 无账号 | 无注册、无登录、无 OAuth、无"用微信/Google 快速登录"。 |

### 4.2 新增：四条可自动断言的护栏

这四条能被 CI 直接判定，比写在文档里的"不做"有用得多。

1. **产物内 0 个网络调用符号**：`fetch(` / `XMLHttpRequest` / `navigator.sendBeacon` / `WebSocket` / `EventSource` 计数必须为 0。**现状不达标**（每站各 1 处 `sendBeacon` + `fetch`，见 §0.3-B），本期要求移除上报分支。
2. **产物内 0 个 CJK 字符**：`[\u4e00-\u9fff]` 计数为 0。**现状 7–23 个**，本期清零（§6.2）。
3. **产物内跨站链接 = 0**：除本站自身 URL 与 `?from=` 携带的 token 外，不得出现其他站的 slug。这条同时防住"页脚矩阵"和"更多房间"。
4. **首屏可见元素 ≤ 3**：`body.l/m` 状态下 `#m` 内可见（非 `hidden`、非 `display:none`、非 0 尺寸）的 `button` + `p` 计数 ≤ 3。

### 4.3 三个最容易滑向的陷阱 + 硬护栏

**陷阱 A：10+ 站变成打卡收集。**
具体形态：`你已访问 3/12 个房间`、隐藏站解锁、彩蛋地图、成就徽章、跨站进度条、统一导航栏、`/` 门户首页。
为什么危险：它把"10 个独立的门"重新粘成一个"1 个 App 的 10 个功能页"，同时制造了"必须走完"的压力——这与"无任务"直接冲突。

> **硬护栏 A1：站与站之间的唯一连接是用户自己复制走的一段 URL 或一段纯文本。产物内不得出现第二个站的名字。**
> **硬护栏 A2：不做门户首页。`/` 要么 404，要么重定向到任意一个站（构建期固定，不可选）。**
> **硬护栏 A3：`?from=` 只允许单向、用户主动、不含任何跨站进度或计数。** 现有 `content/hug.ts:backHint` 的白名单收敛（`['hug','still','license','praise']`）方向正确，扩站时白名单要跟着扩，但**只扩 id，不扩任何计数**。

**陷阱 B：补留存变成连续签到。**
具体形态：`你今天已经来过第 3 天`、streak、每日卡片、`Come back tomorrow`、通知、PWA 安装提示、"上次你在这里停留了 4 分钟"。
为什么危险：它需要把"跨会话状态"持久化，而跨会话状态 + 零 PII 是一对矛盾——你无法在不识别用户的前提下说"你又来了"。

> **硬护栏 B1：localStorage 只允许存"本次会话产生物所需的参数"（种子、草稿、当前状态）。禁止任何形如 `visitedCount` / `streak` / `lastVisit` / `daysSeen` 的键。可自动断言：产物内不得出现这些字符串。**
> **硬护栏 B2：不做通知、不做 PWA、不做"再来一次"倒计时、不做"你离开了"提示。**
> **硬护栏 B3：回访理由只能靠三件事，且必须写进每站配置：(a) 产物再生成且每次不同；(b) 同一 URL 的世界随时间变化；(c) 别人可能回赠。** 缺一项的站不允许上线。

**陷阱 C：补"沉浸"变成补任务链。**
具体形态：把 `/license` 的三段时间轴扩成五步流程、给 `/sink` 加"收集 3 件海底物"、给 `/koi` 加喂食与鱼种图鉴。
为什么危险：每一步都是"完成度"，完成度就是任务。

> **硬护栏 C1：单站的用户动作序列 ≤ 1 个"动作 + 结果"。** 三段时间轴是**一次动作的内部节奏**（用户只按了一次），可以；"收集 3 件"是 3 次动作，不可以。
> **硬护栏 C2：任何形式的选择分支（A 或 B）都要重新论证。** 选择 = 决策成本 = 任务感。首屏不得出现分支。
> **硬护栏 C3：不做"取回"、"撤销"、"重来"以外的一切状态回滚入口。** 状态越少，越不像任务系统。

### 4.4 输入框白名单（零 PII 的具体执行）

全站只允许存在 **1 类** 用户输入：`/miss` 的玻璃写字。

| 属性 | 规定 |
|---|---|
| 渲染位置 | 只在 `<canvas>` 上，不写入 DOM |
| 存储 | 不写 localStorage、不写 sessionStorage、不写 cookie |
| 传输 | 0（产物内无网络符号，见 §4.2-1） |
| 生命周期 | 页面关闭即销毁 |
| 导出 | 允许导出为 PNG（用户主动点击 `Keep this`），导出前**提示一行**：`This stays on your device.` |
| 禁止 | 禁止"分享你的字迹"、禁止回显在 URL、禁止出现在 title/description |

**其余 11 站零输入框。** 包括：不要"输入你的名字让许可证上有你的名字"——那是最容易加、也最容易变成 PII 的一个功能，明确不做。

### 4.5 首屏信息层级（直接回答"信箱横条"）

现状：全屏 3D 背景 + 一个 517×145 的 2D 面板（7.3% 屏面积）+ 十余个可点元素。
新产品：**全屏 canvas 就是舞台，没有"面板"这个概念。**

| 层 | 内容 | 位置 |
|---|---|---|
| L0 | 全屏 3D 世界（biome） | `inset: 0`，承载沉浸与慢变量 |
| L1 | H1（≤2 词）+ hook（≤12 词）+ 主按钮（≤3 词） | 居中，垂直堆叠，无容器框、无背景板 |
| L2 | `Take it with you`（停留 ≥ 阈值后才出现） | 底部，出现时带动画，不抢 L1 |
| L3 | 2D 零件（印章桌/热敏纸/蒲公英/锦鲤） | **合并进 L0**：作为 biome 内的实体存在，不再是一块贴在屏幕上的小画布 |
| L4 | Esc 菜单：Detail / 键位 / Listen / Leave / 风格切换 | 全屏遮罩下的二级面板，默认不可见 |

**关键改动：把 2D 零件从"屏幕上的小画布"改为"世界里的实体"。** 现有实现是 `#stage` 一块 CSS 尺寸的画布浮在 3D 之上；新产品里，2D 零件的绘制结果作为 **billboard/overlay 贴到 3D 世界的某处**（桌面上、水面上），或干脆把 biome 视角直接推向它（`/license` 的桌面即全屏）。这一步是"信箱横条"问题的根因修复，不是尺寸调整。

### 5.3 四个世界如何区分而不破坏统一

**区分只靠四件事，不碰 §5.1 的六件事：**

| biome | 色相区间 | 背景明度 | 主材质 | 慢变量类型 | 禁止 |
|---|---|---|---|---|---|
| `tide` | 195–215° | L 12–18 | 折射 + 焦散 + 体积光 | 光照单调衰减 | 不得出现暖色高光（会把深海变泳池） |
| `field` | 35–55° | L 22–30 | 分层雾 + 颗粒 + 单向风 | 太阳角下降 | 不得出现硬阴影（草原是软的） |
| `room` | 25–40° | L 14–22 | 硬边 + 纸纹 + 单光源 | 环境光色温漂移（冷→暖） | 不得出现景深模糊（室内是清晰的） |
| `ink` | 无彩 + 单色相 260–280° 作 accent | L 70–85 | 纸 + 单色晕染 | 水纹相位 + 鱼群换向 | 不得出现三重以上的颜色（墨只有墨色） |

**统一性的检验方法（人工，写进手测协议）**：把 12 站的凭证 PNG 缩到 200px 高排成一行——如果看不出"同一个机构发的"，视觉系统失败；如果看不出"4 个不同的世界"，世界区分失败。两个都要满足。

### 5.4 动效节奏（数值规范）

| 项 | 规范 |
|---|---|
| UI 过渡 | 500ms，`cubic-bezier(.4,0,.2,1)` |
| 按钮 | 位移 120ms（`translateY(-.12em)` hover / `.1em` active），**唯一允许的快动画** |
| 世界慢变量周期 | ≥ 40s，振幅 ≤ 画布 4% |
| 镜头运动 | ≥ 6s 的缓动，禁止 < 200ms 的镜头跳变 |
| **禁止** | 回弹/overshoot 缓动、无限脉冲、`animation-iteration-count: infinite` 的"吸引注意"循环、粒子的随机跳动（所有粒子必须有单向漂移） |
| 减少动态 | `prefers-reduced-motion: reduce` 时，慢变量振幅降到 0、保留 UI 过渡（500ms 保留，它不引起不适） |

### 5.5 2D 零件重绘规范（可直接指导实现）

现有 4 个 2D 零件（`sites/license/parts`、`sites/praise/parts`、`sites/hug/parts`、`sites/koi/shared/koi.ts`）画风互不相干：license 是矢量桌面、praise 是热敏纸、hug 是蒲公英、koi 是 9 条椭圆。重绘规则：

| # | 规则 | 说明 |
|---|---|---|
| R1 | **零件必须声明 `part.biome`** | 每个零件 manifest 增加 `biome: 'tide'\|'field'\|'room'\|'ink'` |
| R2 | **构建期校验 `site.biome === part.biome`**，不等则 build 失败 | **这是把"语义错位"从人肉 review 变成编译错误的唯一机制。** 现有 `/hug` 挂 dandelion 零件却跑在珊瑚礁世界里，这条规则会让它直接构建失败 |
| R3 | 一律按 `devicePixelRatio × CSS 尺寸` 绘制，禁止固定像素画布 | 现有 koi 用 `ctx.canvas.width` 缩放 ✅；license export 固定 640×880（这是导出件，可保留固定尺寸） |
| R4 | 笔触：单色描边 ≤ 2 CSS px，禁止 `createLinearGradient` 做阴影 | 现有 koi 用单色 `fillStyle` ✅ |
| R5 | 颜色全部取自 biome token，禁止零件自带硬编码色值 | 现状 koi `PALETTES` 自带 3 组硬编码色，需改为从 theme 取 |
| R6 | 纸纹/纸层统一调用 `drawPaper(ctx,w,h)` | 消除 4 套手写噪声 |
| R7 | 零件生命周期三方法：`create(ctx, opts) → update(dt) → dispose()` | 现有 koi 已是此形状 ✅，其余零件对齐 |
| R8 | 零件不得读写 DOM，不得读 `window` 尺寸以外的环境 | 保证可测试、可离屏渲染 |

### 6.3 是否保留任何中文

**产物内：0 个中文字符。** 仓库注释与 `docs/` 保留中文（团队语言）。

**为什么不做双语、也不做语言切换：** 现状的"英文大标题 + 中文小字"不是双语设计，是**两套文案互相削弱**——中文用户读不懂主文案（它决定能不能看懂这一页在干什么），英文用户读不懂副标题（它决定这一页要他做什么）。真正的双语需要两套完整的文案层级（标题、hook、按钮、状态、导出物内文字），成本翻倍且有 50% 的内容永远被一半用户忽略。

**如果未来要中文：** 做法是独立路由（`/zh/still`），一份完整的中文产物，`lang=zh`，不和英文同页。这保持一条不变式：**一个产物只有一种语言。** 这条不变式比"覆盖更多用户"重要，因为它让每站的文案只有一个读者。

### 6.4 一条文案诚实规则（全站最硬）

**不得编造社交证据。** 具体：

- 允许：`Someone kept a seat.`（描述房间状态，不声称有具体的人）
- 允许：`No purchase. Just praise.`（描述本站规则）
- 禁止：`A stranger saved this for you.` / `12 people are here right now.` / `Someone just sent a hug back.`（除非真的发生了，而零服务端意味着我们不知道有没有发生过）
- 禁止：`Come back tomorrow for a new one.`（这是留存话术，也是承诺我们无法履行的东西）

理由：这个产品的全部信用来自于"它不骗你"。一条编造的「有人在想你」能带来即时情绪收益，但它把产品从"诚实的房间"变成"话术生成器"，而这正是 `/praise` 想要对抗的东西。

## 7. 度量与诚实边界

### 7.1 明确不可测的事（必须写明，不许含糊）

| 不可测 | 原因 |
|---|---|
| **留存（D1/D7/回访率）** | 无账号、无 cookie 依赖、localStorage 禁跨会话计数（§4.4-B1）。**我们永远不知道一个人是否来过第二次。** |
| **跨站行为** | 12 个站之间没有任何共享标识。除非用户自己把 `?from=` 带回来，否则"一个人访问过几个房间"无从得知 |
| **情绪改善** | 没有前测后测、没有问卷、没有对照。任何"减轻焦虑/改善睡眠"的表述都是**不可证的**，禁止出现在文案、meta、宣传里 |
| **真实跳出率、页深、会话时长分布** | 单页应用，没有 pageview 序列。任何"跳出率"都是单页会话时长的同义词 |
| **分享链路的后端命中** | 无服务端，`?from=` 是一次性 URL，不知道是否被点开 |
| **来源归因** | 无 referrer 采集（且采集 referrer 就带上了 PII 风险） |

**并且：本期默认不接 analytics endpoint。** 现状 `shared/contract/analytics.ts` 保留 `sendBeacon`/`fetch` 分支（§0.3-B），一旦有人填了 endpoint，"无服务端"立刻失效且没有人会注意到。本期的处理是**删掉网络分支**，只保留 `track()` 的本地队列（用于开发期调试），因此**本期所有运行时指标事实上不可采集**。

### 7.2 两个度量方案（不隐瞒取舍）

> **主理人已裁决：本期采用方案 A。** 理由写在方案 A 下方。方案 B 保留为未来选项，本期不实施。

**方案 A（本期采用）：不接 endpoint。**
度量只剩构建期断言 + 本地手测协议。代价：拿不到任何真实用户数据，产品决策只能靠"读代码 + 人工检查"。换来：`无服务端` 是可验证的事实（产物内 0 网络符号）。

**为什么是 A，而不是 B（主理人裁决理由）：**

1. **"零 PII + 无服务端"是本产品唯一无法被竞品抄走的定位。** 接端点会把它从"可验证事实"降级为"我们的承诺"——而承诺是可以被后来的人悄悄违反的，可验证事实不能。
2. 接端点意味着隐私声明、合规义务（个保法/GDPR 口径）、托管成本、以及一个必须有人长期维护的服务。这三样都和"一个什么都不必做的地方"直接冲突。
3. **本期真正需要回答的问题是"有没有做对"，不是"有多少人来"。** 前者是结构快照 + 人工目验 + 手测协议能回答的；后者在 12 站还没上线、定位还没验证的情况下，即使拿到数字也无法指导决策——那只是给盲赌加一个小数点。

**方案 B（未来选项，本期不实施）：接一个最小 endpoint。**
只记 5 个事件、字段白名单固定、不记 IP/UA/referrer：

| 事件 | 字段（全部） |
|---|---|
| `enter` | `site`, `biome`, `ts_bucket`（小时粒度，不精确到分钟） |
| `primary_action` | `site`, `action_id` |
| `dwell_bucket` | `site`, `bucket`（`0-30s`/`30-120s`/`120-300s`/`300s+`，`analytics.ts` 已有 `bucketDuration`） |
| `artifact` | `site`, `kind`（`png`/`url`/`text`） |
| `exit` | `site`, `reach`（是否到达过 artifact 阶段） |

代价：① "无服务端"不再是卖点，需要写隐私说明；② 即使不记 IP，托管平台的访问日志天然含 IP；③ 需要有人维护这个端点。

**本期确定不打开方案 B。** 如果将来要打开，前提是产品定位已经验证过、且有人愿意承担上述三项代价——不是因为"想看看数据"。

### 8.3 体积门：不放宽（附论证）

4. 如果某个 biome 改造后仍超门，**处理方式是砍内容，不是放宽门**：优先砍 `surface nets` 的分辨率、砍花瓣/草叶密度、砍后处理通道数。
5. **补充（主理人裁决后新增）：8 个站根本不碰体积门。** 按 §2.2，`room`（5 站）与 `ink`（3 站）走 Canvas2D 不内联 WGSL，产物从 ~107 KB 掉到 **~20–40 KB** 量级。只有 `tide`（2 站）与 `field`（2 站）走 raymarcher。**体积风险实际只落在 4 个站上**，且这 4 个站按架构师测算各有 ~51 KB 余量。

### 9.1 会被作废的不变式（写清楚，不粉饰）

> 本节经主理人以源码裁决后修订。初稿曾写"INV-1 作废"，**那是错的**。

**证据（为什么 INV-1a 能活）：**

- `shared/build/resolve-overlay.mjs:9-14`：`resolveOverlay({ coreDir, overrideDir, files })` —— **`coreDir` 本来就是入参**，不是写死的常量。
- `shared/build/build.mjs:117`：`const loaded = resolveOverlay({ ... })`。

所以生态改造的正确落点是：分叉快照放 `shared/biomes/<biome>/`，构建时给 `build.mjs:117` 传**不同的 `coreDir`**。**`shared/core/` 一个字节都不用动。**

- **INV-1a（存活，继续当 CI 硬门）**：`shared/core/` 逐字节等于上游 abyssal-garden `@a596354`。
  没有损失。`npm run verify:core` 的 11 文件校验继续绿；`tests/verify-no-core-write.mjs`（断言构建不写 core）**原样继续有效，无需修改**。
  这不是钻空子：`ARCHITECTURE-NEXUS.md:241` 的 INV-1④ 本来就明文允许"L1 同名替换 `shaders.js`/`main.js`，只要原样保留 5 个常量锚点"。**我们是在用架构文档已批准的路径，不是撬锁。**

- **INV-1b（作废，这才是真损失）**：命题"**所有站点的渲染都源自 L0**，因此站群 = 上游 + 只改配色"。
  一旦站点可以从 `shared/biomes/` 取世界，这个**可机器验证的命题永久消失**。上游将来更新，我们无法再靠哈希说明"我们只差配色"。
  缓解：`shared/biomes/` 里每个生态配一份 `FORK-NOTES.md` 记录相对 L0 的每处改动，并新增 `tests/verify-biome-fork.mjs` 断言"通用段（`W_NOISE`/`W_DETAIL`/`W_POST`）在各生态间逐字节相同"，防止四个分叉各自漂移。**这是损失，不是等价替换。**

**这个区别不是文字游戏**：按初稿的写法，我们要去放宽一个本来还能用的门（`verify:core`）；按事实，我们保住这个门，只承认另一条命题失效。

#### INV-3：**作废，作废范围是逐站而非全量**

`tests/baseline-dist.sha256` 的 7 行**不再全部失效**——而是"**哪个站换 biome，就只重基线哪一行**"，其余行继续有效。

- **作废前**：INV-3 保证"动增量不动存量"，任何对 legacy 站的意外影响都会被字节级拦住。
- **作废后**：这 7 行的语义从"逐字节相等"退化为"重新基线化后的逐字节相等"。**哈希从"回归证据"退化为"变更检测器"**——它能告诉你"变了"，但**再也不能告诉你"变错了"**。
- **治理模型升级**：从"7 站全锁"改为"**逐站锁定 + 换 biome 需显式签字**"。签字记录写进 `tests/baseline-dist.sha256` 的提交信息，每条注明站点、biome、授权来源、签字人。
- **不再需要放宽 `verify-no-core-write.mjs`**（初稿说它"不改则 CI 永久红"，在换 `coreDir` 的落点下不成立）。它继续当硬门，且价值更高：它证明我们在做生态分叉时**没有偷偷回到改 L0 的老路**。

### 9.2 换来了什么

| 代价 | 换来 |
|---|---|
| 失去"**所有站点的渲染都源自 L0**"这一可验证命题（INV-1b） | 12 站从"1 个潜水场景 × 7 套配色"变成"4 个 biome × 12 站语义自洽"。这是用户已拍板的方向，代价不可避免 |
| 失去字节级回归保护 | 换来**语义级回归保护**（§9.3-1 的结构快照 + §9.3-2 的感知差），它能抓住"文案说蒲公英、画面是珊瑚礁"这类哈希永远抓不到的缺陷 |
| 逐站重新基线化（不是全量 7 行作废） | 换来"语义错位"从人肉 review 变成构建期错误（§5.5-R2）。这是一次性成本换永久护栏 |
| —（**未失去**） | `shared/core/` 仍逐字节等于上游，`verify:core` 11/11 继续当硬门；`verify-no-core-write` 继续有效。**这是本次裁决保下来的东西，初稿误判为已失去** |

**一句话**：哈希能保证"东西没变"，但这次的建模前提就是"东西必须变"。继续用哈希当证据，等于用体温计测身高。

### 9.3 哈希不能当证据了，用什么替代（四层，从强到弱）

**第 1 层 · 结构快照（强，自动，可进 CI）**
每站产物提取一份 JSON 结构快照：`{ route, h1, hook, primary_button, visible_first_screen[], lang, title, description, biome, artifact_kinds[], slow_variable_period }`。
断言对象**不是"等于旧值"，而是"等于新设计表"**（本文 §2.4 / §3 的期望值）。
- 它检验"新的对不对"，不检验"没变"。
- 新增站自动纳入。改动一个站，快照 diff 会明确指出哪一项偏离设计表。
- 局限：抓不到视觉质量。

**第 2 层 · 感知差（中，需人工签核，不可称"自动证据"）**
改造期保留一组"只换 biome 参数、其余按旧配置"的参考产物（把 world.js 的 biome 固定为 `abyss`，主题/文案/零件全部用旧值）。用 headless 截图与旧 dist 截图做**像素差 + 感知哈希**，人工复看差异集中在哪里。
- 口径：允许存在差异，但差异应集中在"调色/后处理"区域，**不应出现布局位移、元素消失、构图重构**。
- **必须写明：这不是自动化证据，是人工签核。** 截图 diff 可以自动化生成，但"差异是否可接受"必须有人看过并签名。4 张截图/站 × 12 站 = 48 张，工作量约 2 小时。

**第 3 层 · 不可退化的硬断言（强，自动，仍然有效）**
这些断言在动 world.js 之后**不但仍然有效，价值更高**：

| 断言 | 为什么更值钱 |
|---|---|
| 每站产物 ≤ 163,840 B | 多 biome 是体积的主要风险源 |
| 产物内 0 网络符号 / 0 CJK / 0 跨站链接 | 与 biome 无关，纯回归保护 |
| **站点隔离**：改 A 站配置 → B 站产物字节不变 | world.js 是共享文件，隔离性从"配置隔离"升级为"**biome 隔离**"。这是动 world.js 后最重要的断言：证明"给 `/hug` 加草原不会改变 `/still` 的海底" |
| `site.biome === part.biome` | 新增，抓语义错位 |
| 首屏可见元素 ≤ 3 | 新增，抓"信箱横条"回归 |

**第 4 层 · 手测协议（弱，人工，但不可省）**
§7.4 的 8 项 × 12 站。这是本期唯一能承担"体验质量"的证据。

### 9.4 诚实结论

> **"既有站视觉没有意外退化"这件事，从本期之后永久失去自动证据。** 我们能提供的是：结构快照（证明结构符合新设计）+ 感知差人工签核（证明视觉差异可接受）+ 硬断言（证明体积/纯净度/隔离性没坏）+ 手测协议（证明体验成立）。
> 这四层加起来**不等于**"字节级没有退化"，它只等于"有人用 4 种方式检查过，并愿意签名"。**不接受这一点，就不能做多 biome。** 这是一个二选一，没有第三条路。

### 9.5 前置门 S0：验收能力必须先建成，再写第一行世界代码

**§9.3 的第 2 层（感知差）假设了我们能截屏。架构师查证：今天截不了。**

| 事实 | 证据 |
|---|---|
| core 渲染路径**从未被运行时验证过** | `ARCHITECTURE-NEXUS.md:53` F9 原文；`main.js` 的 WebGPU 初始化在任何测试里都没被真正执行过 |
| 现有探针跑不了 | `tests/probe-webgpu.mjs:13` 硬编码 `C:/Program Files (x86)/.../msedge.exe`；`tests/runtime-smoke.mjs:12` 同样。本机只有 Safari |
| 没有浏览器自动化依赖 | `package.json` 的 devDependencies 只有 `three` / `esbuild` / `tsx` / `typescript`，**无 Playwright / puppeteer** |

**所以 S0 必须排在一切实现之前，且它自己就是一道门：**

1. **L1 · CPU 结构摘要（免费、精确）**：把 `makeWorld` 返回值里的 `big.n / small.n / chunks[i].n / props[i].n / solids.ranges.length / glints.length / fish.length / bubbles.length` 连同 `T.nv / T.ni` 打成一份 JSON golden。抓 `world.js` 的回归，覆盖约 81% 会出错的代码。**局限：不涉及密度网格 D（D 是 GPU 算的），抓不到 `dens()` 的回归。**
2. **L2 · SDF 指纹（需 GPU）**：D 计算完成后量化到 1 cm 做 64-bit FNV（`main.js:164` 本来就在 `mapAsync` 读回，顺手算约 300 B 代码），打到 console 供 CDP 抓取。**这才是唯一能抓 `dens()` 回归的手段。**
3. **L3 · 冻结截图（模糊、同机）**：必须冻 `LV` / `pix` / `det` / `devicePixelRatio` / viewport / `F[TIME]` / camera pose 七个变量。**注意 `quality.js:13` 存 localStorage、`main.js:534-551` 每秒自动调 `pix`/`det`，当前代码没有任何 URL 参数能关掉这个调参器**——像素级相等不可达，只能用"降采样 + 每格均值容差 + 3 帧中位数"，且**只能同机同 GPU 比对**。

**S0 的通过标准**：连续 3 次截图字节相等。

**如果 S0 失败**（headless WebGPU 在本机确实拿不到，SwiftShader 也跑不动），**正确决策不是硬做 12 个站**，而是：把 biome 压到 2 个、每站配人工目验签字、并明确告知"12 站的视觉一致性无法自动保证"。**这个判断必须在 S0 做完后立刻下，不要等到第三个生态写完才发现没证据。**

**为什么这一条是 PRD 的事而不是纯工程的事**：它决定这份文档里"12 站"这个数字能不能兑现。产品承诺必须建立在可验证的交付能力上，所以 S0 是本 PRD 的**前置门，不是附录**。
