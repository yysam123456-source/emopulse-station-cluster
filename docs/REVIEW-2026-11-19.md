## 0. 三句话结论

1. **这不是一个 three.js 项目，是一个 Canvas2D 图层拼贴器。** 仓库里有 4,473 行 three.js 代码（koi / room-at-dawn / grand-atelier / rain-webgpu），**四个产物里 three.js 字节数为 0**。产品叙事（"一个物理现场""真实叠加"）与运行时（6 层 2D 画布 + 1 条 GL 通道 + `drawImage`）错配，这是后面所有具体问题的根。
2. **验证体系测的是零件统计，不是成品画面。** 117/117 + 80/80 全绿的同时：`/koi` 没有鱼、整屏字符盖住标题；`/hug` 没有蒲公英；`/still` 没有 `Sit`、22 fps；Esc 菜单 6 个按钮全是死的；导出图不是屏幕上那张。
3. **预算模型测的是 JS 估算，不是 GPU 真实帧。** 唯一真正超时的 `/still` 在账本上只花 **0.05 ms**，永远不会被降档；而"无上限叠加"会先把 L4（最贵、且 `expendable`）挂起——把最像"复合"的那层先砍掉。

## 2. 五个结构性问题

### 2.1 定位错配：three.js 资产库 vs Canvas2D 运行时（P0）

- `package.json` 里有 `three ^0.169`，但 `shared/parts/*` 七个零件里 **6 个是 `canvas2d`，1 个是原生 WebGPU**（`voxel-world`）。
- 全仓 `from 'three'` 的文件合计 **4,473 行**，全部在 `shared/parts-library/`（legacy）。
- 四个 `dist/*/index.html` 里 `THREE|WebGLRenderer` 的出现次数：**0 / 0 / 0 / 0**。
- `shared/stage/stage.ts` 的通道模型：`draw()` 只允许 **一个 GL 画布、全场唯一**，`compositeGl()` 用 `drawImage` 把它拍平进 2D。

后果不是"少用一个库"，而是产品上限被锁死：

- 2D 与 3D 不能按深度互相遮挡（纸永远在 3D 之上或之下，不能"纸在桌上、笔在纸前"）。
- 只能有一个 3D 场景；`/koi` 的水 + 鱼 + 荷叶要么全在 3D，要么全在 2D，不能"鱼在水下 3D、墨在纸面 2D"。
- three.js 的材质/光照/后处理/实例化全部用不上；"叠加"只能靠 `globalCompositeOperation` 贴纸片。
- 最贵的资产被最便宜的复刻替代：`parts-library/koi/README.md` 明写"realistic / watercolour / ink 三种风格、每帧只动 16 个脊点、1,600 行、无依赖"；现在 `/koi` 用 ASCII 复刻，**结果没有鱼**。

### 2.2 验证体系看不见"成品"（P0）

现有门按"零件/结构/色相"测，缺"整页"这一层：

| 门 | 测什么 | 漏什么 |
|---|---|---|
| `site-build` 117 条 | 文案、DOM、配色、尺寸、单文件 | 画面里有没有主体 |
| `site-dom` 80 条 | 三层文案、按钮、菜单存在 | 按钮有没有 handler |
| `site-fingerprint` | 全帧色相中位（宽 ±25°） | 占据率、对比度、可读性 |
| `ascii-field` 的 K1/K1b/K3 | 行偏移、同字符连长、灰阶占比 | 有没有鱼、有没有盖住 UI |
| `license-stay` | 像素变化量 | 变化是不是"对的"变化 |

三个直接后果：

- **假按钮**：`shared/sites/copy.mjs` 定义了 6 个菜单项（Sound / Motion / Quality / About / Credits / Close），
  `shared/sites/shell.ts` 只渲染、**没有任何 click handler**。Esc 能开，Close 关不掉。
- **空主体**：`STATIONS.hug` 只有 `field-ground` + `pixel-post`，`dandelion` / `boids` / `blow` 都没装；
  `STATIONS.still` 没有 `tide-medium`，没有 `pixel-post`。文档写的是"4–6 件"，代码是 2 件。
- **色相门被当成质量门**：`/koi` 的"近无彩"通过，但画面是一堵字墙。色相合格 ≠ 画面成立。

`docs/PRODUCT-FORM.md §6.4` 自己写过"画面好不好看，目前没人看过"。这次看了：**四站里只有一站成立。**

### 2.3 预算 / 降档模型建立在错误的量上（P0）

- `stage.ts`：`DEFAULT_BUDGET_MS = 8`，`planBudget()` 用零件自报的 **静态 `costMs`** 求和，超了就整档 `setLod('low')` / 挂起 `expendable`。
- `voxel-world/index.ts`：`costMs: 0.05`。实测 `/still` **22.7 fps**（≈44 ms/帧），账本上它是全场最便宜的零件。
  也就是说：**唯一的真瓶颈对预算系统不可见**，它永远不会被降档。
- `pixel-post/index.ts`：`costMs` 最高且 `expendable: true`。叠加越多 → 越先挂起 L4 → 颗粒、暗角、扫描线先消失，
  而这三样正是"复合感"的来源。**激励方向反了。**
- `8 ms` 的预算与"无上限、不断叠加"直接冲突；叠加的物理上限不是零件数，是 GPU 填充率/带宽，而当前没有任何 GPU 计时。

**内存**：`pixel-post` 在 `bakeOverlays()` 里烘 **8 张全屏覆盖图**（`GRAIN_PHASES = 8`）。
1280×800 @dpr1 ≈ 32.8 MB；@dpr2 ≈ 131 MB；2560×1440 ≈ 118 MB。这不是"优化项"，是移动端/4K 的稳定性问题。

### 2.4 层号被当成物理层，而不是渲染顺序（P1）

`L0 底材 / L1 世界 / L2 生态 / L3 响应 / L4 后处理 / L5 DOM` 是**绘制顺序**，文档却拿它当**空间深度**用：

- "L0 只能当地板或骨架" → `/still` 的 L0 水色被 L1 体素盖住，只好把水写成 L1 的"介质"。
- "纸必须可见 → 纸是 L2" → `/license` 的纸被归到"生态层"，语义上很别扭。
- "L1 全场唯一" → 一个 3D 场景，无法同时有"房间"和"纸上的 3D 印章"。

真正该有的是四个**角色**：`world`（环境）、`subject`（用户动手的那件东西：纸/塘面/蒲公英）、
`input`（指针/风/麦克风）、`post`（胶片），外加 `ui`。层号可以保留，但必须允许：
**subject 在 world 之前或之后**（纸在桌上 = subject 在 world 之上；鱼在水下 = subject 在 world 之下）。
否则每加一个站都要为"谁盖谁"打一次补丁。

### 2.6 站点与零件之间没有受控通道（P1）

现在的契约是"零件只读 `WorldFrame`，不许反向调用"。纪律是对的，但缺三样东西，导致每个站都要复制一遍：

1. **几何发布**：纸框/地平线/塘面在哪，L5 不知道 → `shell.ts` 抄公式（§2.5）。
2. **站点 → 零件命令**：盖章、下潜、起风，只能由站点自己实现（`license/ritual.ts` 165 行），
   `/still` 想"坐下"就必须再写一遍。文档说"现在允许抽"，但契约里没有可抽的接口。
3. **图层画布/RT**：零件想"只画在纸内"、"先画到离屏再按 blend 合成"，只能自己 `save/clip` 或干脆画全屏（`/koi` 的字墙）。

## 3. 调整方案（按代价/收益排序）

### 第 0 步（半天）：先把"成品"变成可验收对象

新增 `npm run verify:site`：对四站各截一张首屏 + 60 秒后一张，算 6 个数：

1. **主体存在**：该站 `subject` 零件的非背景像素占比 ≥ 3%（鱼/蒲公英/纸/水面）。
2. **文字安全区**：H1/hook/CTA 的包围盒内，背景方差 ≤ 阈值（不被高频内容压住）；与主体重叠面积 ≤ 10%。
3. **对比度**：文字与局部背景的 WCAG 对比 ≥ 3:1（大字）/ 4.5:1（正文）。
4. **占据率**：每个零件的"非透明像素/整页"落在规格区间（ASCII ≤ 纸面 60%，纸面 55–80%）。
5. **运动量**：60 秒内帧差中位 ≥ 某值（证明"活着"），且 ≤ 某值（证明"不吵"）。
6. **带走物存在**：每站至少一条可导出/可复制的产物路径。

这一步不改任何架构，只让"全绿但难看"不再可能。

### 第 1 步（1 周，P0 修复，不动底座）

- **`/koi`**：把 `parts-library/koi` 的 ink 风格接回来做 L1（它自带 `?seed`、`?q` 自适应、三种风格）；
  ASCII 降级为"纸上的墨层"，**必须 `clip` 到纸框**，且只保留 1–2 层墨，不做满屏。
  这一步同时验证"资产库真的能用"。
- **`/still`**：装 `tide-medium` 做 L0（已有）；加 `Sit` CTA + 光衰减慢变量；加载期给遮罩（现在 `state: ready` 是假的，
  `voxel-world` 的 `create` 立即返回、`draw` 是空操作，用户看到几十秒黑屏）。
- **`/hug`**：装 `dandelion` + `boids` + `sun`；修布局（hook 在按钮下方、贴底、压草）；
  实现 `?from=hug` 的"带走"（现在只有文案，没有产物）。
- **Esc 菜单**：6 项要么实现（Sound 开关环境音、Motion 切 `reducedMotion`、Quality 调 `renderScale`、Close 真关），
  **要么删掉**。挂一个点了没反应的按钮，比没有更糟（这是文档自己写过的话）。
- **导出**：先改成"裁当前帧"（`drawImage(canvas)`），与屏幕一致；L4 的颗粒/暗角必须一起裁进去。
  代价是导出分辨率受屏幕限制——那就把渲染尺寸临时抬到 2× 再截（见第 2 步的 `renderScale`）。

### 第 2 步（2–3 周，底座升级，不动产品）

把 stage 从"2D 合成器 + 1 条 GL 通道"升级为 **"2D 合成器 + 可复用的 three.js world 层"**：

```
Stage
├─ L0  2D: 底材（纸/水色/天空）        canvas2d
├─ L1  world: three.js 场景（1 个 renderer，N 个 world part 共享）
│      camera / fog / lights / instanced meshes / shader materials
├─ L2  2D: 主体与墨/雾/尘              canvas2d（clip 到 subject 区域）
├─ L3  input: 指针/风/音频             uniform / decal
├─ L4  post: grain/vignette/scanline   canvas2d（作用在整幅，含 world）
└─ L5  DOM: 文案/菜单/CTA              DOM
```

关键改动只有四条：

1. **`channel: 'gl'` → `channel: 'world'`**：允许 N 个 world 零件共享一个 three.js `Scene`/`Renderer`
   （`worldId` 分组），stage 负责 `renderer.setSize/setPixelRatio`、`dispose`、resize。
2. **`costMs` 降级为"静态提示"**，真实预算改用 **frame-time EMA + `renderer.info` + GPU timer（可用时）**，
   调 `renderScale`（0.55–1.0，3 帧降 / 10 帧升，带迟滞）；`L4` **永不可挂起**。
3. **`pixel-post` 内存**：8 张全屏覆盖 → 1 张 vignette+scanline + 1 张 128² grain（`createPattern`），
   或一个 `DataArrayTexture` + 一个全屏 `ShaderPass`。@1440p 从 ~118 MB 降到 ~15 MB。
4. **契约加两个受控接口**（不是后门）：
   - `describe(): { subjectRect?, horizon?, safeAreas? }` —— 零件发布几何，L5 不再抄公式；
   - `cue(name: 'stamp'|'sit'|'wind'|'fold', payload?)` —— 站点驱动零件，仪式/状态机可复用。

### 第 3 步（4–8 周，资产归位）

- `parts-library` 的 three.js 资产逐个升级为 `shared/parts/<name>/` 的 **world 零件**：
  `koi`（ink/watercolour）、`room-at-dawn`（`/license` 的"房间+晨光"）、`grand-atelier`（材质/光照参考）、
  `rain-webgpu`（雨/折射参考）。
- `voxel-world` 保留为 `/still` 的 **world provider**（它是目前最惊艳的一块，不要为了"统一"把它做掉）。
- 三套介质各定一条"物理前提卡"（光向、介质、风/流、相机），构建期校验零件与前提是否冲突
  （例如：3D 水 + 2D 纸 = 冲突；纸在房间里 = subject 必须在 world 之后）。

### 第 4 步（持续）：文档收敛

- `PRODUCT-FORM` 与 `HANDOFF` 的 5 条冲突逐条裁决，写进一张 `DECISIONS.md`（只记"谁赢了、为什么"）。
- `ARCHITECTURE-REUSE` / `PRD-REUSE` 移入 `docs/archive/`；算法清单抽成 `tests/fixtures/provenance.json`，
  让 `verify:reuse` 读 fixture，不读 232 KB 文档。
- `docs/README` 只留 6 份活文档；新文档必须挂"状态 + 输入/输出"。

## 4. three.js 落地蓝图（技能 → 具体落点）

只列真正会用到的，避免"把所有技能都念一遍"。

| 技能 | 落到哪 | 具体做法 |
|---|---|---|
| `threejs-renderers` | world 层唯一 renderer | `WebGLRenderer({ antialias:true, powerPreference:'high-performance' })`；`setPixelRatio(Math.min(dpr,2))`；`outputColorSpace = SRGBColorSpace`；`toneMapping = ACESFilmicToneMapping`（水下/房间）或 `NoToneMapping`（纸面插画）；`autoClear=false` 按 role 顺序画；resize 时 `setSize` + composer `setSize` |
| `threejs-scenes` | `/hug` `/still` 的深度 | `FogExp2`，雾色 = `scene.background`，消掉 `/hug` 现在那条硬地平线；`/still` 用指数雾做"越深越暗" |
| `threejs-lights` | `/license` 的晨光 | `DirectionalLight` + `castShadow`（纸/桌/章），拖光 = 转 `light.position`，阴影真的跟着走；`HemisphereLight` 补天光；阴影贴图 1024，`bias/normalBias` 按场景尺度调 |
| `threejs-materials` | 纸/水/墨 | 纸：`MeshStandardMaterial` + 噪声 roughness/normal（或 `ShaderMaterial`）；水：koi 的 `ShaderMaterial`（折射/焦散）；气泡：`AdditiveBlending` + `depthWrite:false`；墨：`multiply` 混合的贴图 quad |
| `threejs-objects` | 草/鸟/种子/气泡 | `InstancedMesh`：草 560、boids 120、种子 1,335、气泡 70；`Raycaster` + `layers` 做"点鱼/点纸"；`dispose()` 随零件 |
| `threejs-geometries` | 草叶/纸/鱼 | 草叶 `BufferGeometry` 两三角 + 顶点风；纸 `PlaneGeometry`；鱼用 koi 的 52×24 lofted tube |
| `threejs-textures` | 纸纹/颗粒/环境 | `CanvasTexture` 纸纹（一次性生成）、`DataTexture` 颗粒（128² 平铺）、`PMREMGenerator`（若用 PBR 房间）；albedo `colorSpace = SRGBColorSpace`，数据贴图保持线性 |
| `threejs-loaders` | 资产 | 若有 glTF：`GLTFLoader` + `DRACOLoader` + `KTX2Loader`；koi 是程序化几何，无需 loader；import 用 `three/addons/...` |
| `threejs-postprocessing` | world 内 bloom/DOF | `EffectComposer` + `RenderPass` + 半分辨率 `UnrealBloomPass`（水下光柱）；**胶片颗粒/暗角留在 L4**，因为那是"整页胶片"，不是"世界光学" |
| `threejs-camera` | 双相机 | world 用 `PerspectiveCamera`（fov≈50）；screen 2D 用 `OrthographicCamera`；指针视差 = 相机 `position` 微移，不做 orbit |
| `threejs-dev-setup` | 版本/导入 | `three ^0.169` 偏旧，升到当前线并锁版本；只允许一份 `three`；esbuild 已够，无需 Vite |
| `threejs-animation` | 盖章手臂 | 若做"手臂/杠杆"用 `AnimationMixer` + 手写 clip；程序化运动（水/草/鱼）不用 mixer |
| `threejs-helpers` | 开发期 | `CameraHelper` 调阴影视锥、`AxesHelper` 对纸面坐标；不进产物 |

**不建议现在做的**：`WebGPURenderer` + TSL（`threejs-node-tsl`）全量迁移——`/still` 已有原生 WebGPU，
再叠一层 node 材质会把"能跑"变成"要调"；等 `/koi` `/license` 的 WebGL 路径稳定后再评估。
`threejs-webxr` 现在不需要，但 world 层用 `setAnimationLoop` 可以保留 XR 入口。

## 5. 产品矩阵（逐站处方）

| 站 | world | subject | 一个动作 | 慢变量（≥40 s） | 带走 | 现状 |
|---|---|---|---|---|---|---|
| `/license` | 暗桌/房间 | 纸 | 盖章 | 光角 6°/4 min | 编号 + PNG | 4/5（导出不符） |
| `/hug` | 草甸 | 蒲公英 | 吹/放飞 | 日落 + 风向 | 链接 `?from=hug` | 2/5（无主体/无慢变量/无带走） |
| `/still` | 水下 | 水面/光柱 | `Sit` 下潜 | 光衰减 | 五句话 | 2/5（无动作/无慢变量/无 L0） |
| `/koi` | 池 | 鱼 + 墨 | 划水 | 鱼群换向 | PNG + `?seed` | 1/5（无鱼/无墨/无带走/画面崩） |

产品侧三条判断：

1. **"四站"不是四个功能，是四个物理现场。** 每个现场必须同时有 world + subject，否则就是壁纸。
   `/hug` 现在有 world 没有 subject；`/koi` 两个都没有；`/still` 有 world 没有动作。
2. **首屏三层要按"视线顺序"排，不是按"固定坐标"排。** 现在 `#lead` 在 `bottom: 6vh`、`#cta` 在 `bottom: 11.5vh`，
   按钮在文案**上方**，信息层级是倒的；`/koi` 的 H1 被字墙压住，对比度不够。建议每站给一组布局 token
   （H1 锚点相对地平线/纸框、hook 紧跟 H1、CTA 在下三分之一），并用第 0 步的"安全区"门校验。
3. **"不承诺疗愈"是对的，但"不解释"不等于"没内容"。** 四站现在的文案都很克制，这是优点；
   但克制要靠**物理细节**托住（光的移动、水的折射、鱼的换向），而不是靠留白。留白 + 空画面 = 没做完。

## 8. 风险与代价（诚实版）

- **包体**：three.js tree-shaken core 约 120–150 KB gzip；koi 资产另计。四站现在 30–128 KB，接 three.js 后
  首屏会到 300–500 KB。对"情绪站"可接受，但要按站裁：`/license` 不需要 koi 的整套 shader。
- **性能**：单渲染器 + 多 RT 的带宽成本高于 2D 合成；`/still` 现在 22 fps，接 three.js 不会自动变快。
  先把 `renderScale` 和 LOD 做对，再谈"无上限叠加"。
- **WYSIWYG**：导出仍是第二套排版，除非把"版式"抽成数据模型（DOM 与 canvas 共用一份 `LicenseLayout`）。
  这是 2–3 天的活，不做就会一直"屏上一张、导出另一张"。
- **双后端**：WebGPU（`/still`）+ WebGL（three.js）要两套能力探测；`detectCapabilities` 现在只看
  `navigator.gpu` 是否存在，不看 adapter，会误判。
- **文档债**：这次评审本身也会变成第 5 代文档；所以它被标成"输入"，且只保留 6 份活文档。
